1. The state-action value function Q(s,a): definition

This is described as the key quantity reinforcement learning algorithms compute. It's a function of two inputs — a state s and an action a — and it outputs a single number.

Q(s,a) = the return if you: (1) start in state s, (2) take action a once, (3) then behave optimally after that.
Analogy: imagine grading a single chess move by imagining a grandmaster takes over immediately afterward. Q(s,a) doesn't ask "was this move part of a good overall game" — it asks "if I make exactly this one move right now, and then play perfectly for the rest of the game, how good is the final outcome?" It isolates the value of one specific choice against a backdrop of otherwise-perfect play.
What Q(s,a) is NOT: it does not judge whether action a was a good idea. It faithfully reports the return you'd get by taking that action and then playing optimally — even if a is actually a poor choice compared to the alternative. Section 3's worked example makes this concrete: going right from state 2 gives Q(2,→) = 12.5, a perfectly well-defined number, even though right is not the better move from state 2 (going left is, per Section 5).

2. The slightly circular definition — and why it's okay

There's a real logical wrinkle here worth sitting with, because it's easy to gloss over: Q(s,a) is defined in terms of "behaving optimally after that" — but behaving optimally means already knowing the optimal policy. And if you already know the optimal policy, why would you still need to compute Q(s,a) at all?

Why this isn't a dead end: the lecture explicitly flags this as circular-looking but promises it gets resolved once actual RL algorithms are introduced (later in the course, beyond this file's scope). The resolution, in brief: RL algorithms find a way to estimate Q(s,a) before knowing the optimal policy — the policy is then read off from the estimated Q values (Section 5), rather than needing to be known in advance. For now, the material just asks you to accept the definition and see how useful it is once computed, without worrying about how the circularity gets broken.
What to take away for this part of the week: treat "behave optimally after that" as a given, fixed reference behavior — in the Mars rover example, that reference behavior is a specific, already-known policy (left from states 2, 3, 4; right from state 5). All the Q(s,a) values worked out in this section are computed relative to that particular policy, not derived from nothing.

3. Worked examples: computing Q(s,a) by hand

Using the policy "left from 2, 3, 4; right from 5" and γ = 0.5:

Example 1 — Q(2, →)

1Start in state 2, take action right (once) → you land in state 3.
2From state 3 onward, behave optimally (per the reference policy): go left, left, reaching the reward of 100.
3Reward sequence: 0 (state 2) → 0 (state 3) → 0 (state 2 again) → 100 (state 1).
Q(2, →) = 0 + (0.5)(0) + (0.5)²(0) + (0.5)³(100) = 12.5

Example 2 — Q(2, ←)

1Start in state 2, take action left (once) → land directly at state 1 (terminal, reward 100).
Q(2, ←) = 0 + (0.5)(100) = 50

Example 3 — Q(4, ←)

1Start in state 4, take action left → state 3 → (behaving optimally) left → state 2 → left → state 1.
2Reward sequence: 0, 0, 0, 100.
Q(4, ←) = 0 + (0.5)(0) + (0.5)²(0) + (0.5)³(100) = 12.5
Notice Q(2,→) and Q(4,←) come out equal (12.5). That's not a coincidence — both describe ending up at state 3 after one action, then behaving optimally from there, so they have the same future path and the same discounting. This hints at something important that Section 9's derivation makes explicit: Q(s,a) can always be broken into "where does this one action land me" plus "what's the best return from there."

5. From Q(s,a) to the best action

Best possible return from state s  =  maxa Q(s,a)

Best possible action in state s  =  the action a that achieves maxa Q(s,a)

Looking at the table above: in state 4, Q(4,←) = 12.5 is larger than Q(4,→) = 10, so 12.5 is the best possible return from state 4, and "go left" is the best action there. In state 5, Q(5,→) = 20 beats Q(5,←) = 6.25, so "go right" is best there.

Why this is the payoff of computing Q(s,a) at all: once Q(s,a) is known for every state and action, finding the optimal policy no longer requires any further reasoning about the future — you just look at the current state, check Q(s, left) vs. Q(s, right) (or however many actions exist), and pick whichever is larger. All the "thinking ahead" is already baked into the Q values themselves.
π(s) = argmaxa Q(s,a)
Terminology note: in the reinforcement learning literature, this Q function (computed using the truly optimal policy) is sometimes written Q* and called the optimal Q function. The lecture mentions this only so the terms aren't confusing if encountered elsewhere — for this course, "Q function" and "Q*" refer to the same thing.

7. Why we need the Bellman equation at all

Section 1–6 computed Q(s,a) by brute force: write out the entire future reward sequence from that state onward and sum the discounted terms by hand. That works fine for a 6-state toy example, but it's clearly impractical for any real problem — you can't hand-enumerate every future reward sequence for a helicopter or a chess game.

Why this matters: the Bellman equation gives a way to express Q(s,a) recursively — in terms of the Q-values of other states — rather than requiring the entire infinite future to be summed out explicitly every time. This recursive structure is what actual reinforcement learning algorithms exploit to compute Q(s,a) without brute-force enumeration.

8. Bellman equation notation, piece by piece

SymbolMeaning
sthe current state
athe current action (taken in state s)
R(s)the reward of the current state — e.g. R(1) = 100, R(2) = 0, ..., R(6) = 40
s′the state you land in after taking action a from state s (e.g. from state 4, going left lands you in s′ = 3)
a′the action you might take in the new state s′
Naming convention: unprimed symbols (s, a) always refer to right now; primed symbols (s′, a′) always refer to the next state and the action taken there. This convention is used consistently throughout the Bellman equation and its derivation.

9. The Bellman equation itself

Q(s,a) = R(s) + γ · maxa′ Q(s′, a′)
TermInterpretation
R(s)the immediate reward — what you get right away, just for being in state s
γ · maxa′ Q(s′, a′)the discounted best possible return from the next state s′ onward
Analogy: think of planning a road trip cost. "Total cost of the trip starting from here" = "cost of the very next leg of the journey" + "cost of the rest of the trip, starting from wherever that next leg ends." You don't need to know the whole trip's cost in one giant calculation — you only need to know today's leg, plus a (recursively defined) number representing everything after today. The Bellman equation applies exactly this decomposition to returns: reward right now, plus the discounted value of the best possible future starting from wherever you land next.

10. Full derivation: why the Bellman equation is true

This is worth working through carefully once, since "why is this true" is more valuable long-term than just memorizing the formula.

Step-by-step derivation

1Start from the definition. By definition, Q(s,a) is the full discounted return starting from state s, taking action a, then behaving optimally:
Q(s,a) = R1 + γR2 + γ²R3 + γ³R4 + ⋯
2Split off the very first reward. R1 is just R(s) — the reward for the state you're currently in. Factor γ out of everything else:
Q(s,a) = R(s) + γ [ R2 + γR3 + γ²R4 + ⋯ ]
3Recognize the bracketed term. After taking action a from s, you land in state s′. The rewards R2, R3, R4, ... are exactly the sequence of rewards you'd see if you started fresh from s′ and behaved optimally from there onward. That is precisely the definition of the best possible return from s′:
R2 + γR3 + γ²R4 + ⋯ = maxa′ Q(s′, a′)
4Substitute back. Replacing the bracketed term with maxa′ Q(s′,a′) gives exactly the Bellman equation:
Q(s,a) = R(s) + γ · maxa′ Q(s′, a′)
Why step 3 is the heart of the whole derivation: it relies on the Markov property from Part 1 (Section 8) — once you know you're in state s′, it doesn't matter how you got there (via s and action a, in this case); the best possible future from s′ onward is always maxa′ Q(s′,a′), full stop. That's what allows "the rest of the return" to be replaced by a clean, self-contained quantity instead of needing to track the whole history.

11. Worked Bellman-equation examples

Recomputing the same two examples from Section 3, now using the Bellman equation directly instead of summing an infinite series by hand:

Q(2, →) via Bellman

1s = 2, a = →, so s′ = 3 (going right from state 2 lands you in state 3).
Q(2,→) = R(2) + 0.5 · maxa′ Q(3, a′) = 0 + 0.5 × max(25, 6.25) = 0 + 0.5 × 25 = 12.5

Q(4, ←) via Bellman

1s = 4, a = ←, so s′ = 3 (going left from state 4 also lands you in state 3).
Q(4,←) = R(4) + 0.5 · maxa′ Q(3, a′) = 0 + 0.5 × max(25, 6.25) = 0 + 0.5 × 25 = 12.5
Both match the brute-force answers from Section 3 exactly — 12.5 and 12.5 — confirming the equation is doing the same job as summing the whole future series, just without having to write the whole series out. Also notice why Q(2,→) and Q(4,←) came out equal back in Section 3: both actions land in the exact same next state (s′ = 3), so the Bellman equation trivially gives them the same value — R(2) = R(4) = 0, and both use the same maxa′ Q(3,a′) term.

12. The special case of terminal states

Q(s,a) = R(s)   (for terminal states — the maxa′ Q(s′,a′) term simply disappears)
Why: in a terminal state, there is no s′ — the process ends, so there's nothing for the second term of the Bellman equation to refer to. That's why Q(s,a) at states 1 and 6 is just 100 and 40 respectively, regardless of which action is nominally taken there.

13. Stochastic (random) environments

Everything so far assumed that commanding "go left" always, reliably, results in going left. Real systems are rarely this obedient — a real Mars rover might hit a rockslide or slippery terrain and end up moving in the direction opposite to the one commanded.

Command: go left  →  90% chance of actually going left, 10% chance of accidentally going right
Command: go right  →  90% chance of actually going right, 10% chance of accidentally going left

Commanding "left" from state 4 succeeds 90% of the time; 10% of the time the rover slips and ends up moving right instead.

Why this matters: once actions have uncertain outcomes, the whole notion of "the return" from following a policy stops being a single fixed number. Running the exact same policy twice from the exact same starting state can produce two completely different reward sequences, depending on when (if ever) a misstep happens. The lecture material walks through this explicitly — following "left, left, left" from state 4 might succeed every time and yield rewards 0,0,0,100, or might slip once midway and take a longer, different path, or might even slip on the very first step and end up heading toward the other terminal reward entirely.

14. Expected return

Since the return itself is now a random quantity (it depends on which sequence of missteps happens to occur), maximizing "the return" no longer makes sense as a well-defined goal — there isn't one fixed number to maximize. Instead, the goal becomes maximizing the expected (average) return.

Expected Return = Average( R1 + γR2 + γ²R3 + γ³R4 + ⋯ ) = E[ R1 + γR2 + γ²R3 + γ³R4 + ⋯ ]
Analogy: this is exactly the same idea as expected value in a casino game. You can't say in advance exactly how much you'll win on any single hand — that depends on the random cards dealt — but you can compute (and try to maximize) the average amount you'd win if you played the same strategy thousands of times. "Expected" is statistics-speak for "average" here, nothing more exotic.
Updated goal of reinforcement learning: in a stochastic environment, the goal becomes — choose a policy π(s) = a that tells us what action to take in state s, so as to maximize the expected return, rather than a single guaranteed return.

15. The Bellman equation under randomness

Q(s,a) = R(s) + γ · E[ maxa′ Q(s′, a′) ]

The equation keeps exactly the same shape as before — immediate reward plus discounted future value — with one change: since s′ is now random (a given action from state s might lead to different next states depending on chance), an expectation (average) operator E[...] wraps the future-value term.

Why only this one change: the deterministic-case derivation in Section 10 still holds conceptually — Q(s,a) is still "reward now, plus discounted value of the best future from wherever you land." The only thing that's changed is that "wherever you land" (s′) is no longer a single guaranteed outcome, so the "value of the future" term has to be averaged over all the states you might land in, weighted by how likely each one is (e.g. 0.9 × [value if s′ = 3] + 0.1 × [value if s′ = 5] for the misstep example in Section 13).

16. Optional lab: the misstep probability

The same notebook from Section 6 includes a misstep_prob parameter (0 by default, meaning fully deterministic). Setting it above 0 makes the simulated rover's actions unreliable.

misstep_probEffect on Q(s,a) values and optimal return
0.1Q values and the optimal return at every state decrease somewhat, compared to the deterministic case — you have less control over the robot, so the guaranteed value of being in any state goes down
0.4Values decrease further — with 40% of actions going the "wrong" way, the rover's degree of control has dropped substantially, and this is reflected directly in lower Q(s,a) and lower optimal (expected) returns throughout
Why this matters intuitively: Q(s,a) values dropping as misstep probability rises is a very natural finding — the less reliably your actions translate into intended outcomes, the less any state is "worth" to you, even holding the reward structure and discount factor fixed. This is a clean, hands-on way to see that uncertainty itself has a cost in an RL problem, visible directly in the numbers.
