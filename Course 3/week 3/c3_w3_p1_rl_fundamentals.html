1. Why a new framework? What reinforcement learning is for

Everything covered so far in the specialization — supervised learning, collaborative filtering, content-based filtering — shares one thing in common: you're given a fixed dataset of correct answers (labels, ratings) and you train a model to predict them. Reinforcement learning (RL) is a different setup entirely: there's no dataset of "correct actions" to imitate. Instead, there's an agent that takes actions in a world, and the world responds with a reward signal telling the agent roughly how good or bad that action was — and the agent has to figure out, through trial and consequence, what sequence of actions leads to the best outcomes.

Why this matters: in many real problems — flying a helicopter, playing chess, controlling a robot — nobody can hand-label "the correct control input for this exact helicopter orientation." It's far easier to say "this outcome is good" or "this outcome is bad" (crashing is bad, reaching the goal is good) than to specify the correct action for every possible situation in advance. RL is built specifically for problems where you can define what a good outcome looks like, even if you can't specify the correct action directly.
Analogy: training a dog. You can't write down the exact muscle movements you want the dog to make. What you can do is give it a treat when it does something you like and withhold it when it doesn't — and over repeated attempts, the dog works out a strategy that earns the most treats. RL formalizes this "reward-shapes-behavior" idea into an algorithm.

2. The running example: the Mars rover

The whole week's discussion is anchored to one simplified example: a Mars rover that can be in one of 6 states, laid out in a line.

The Mars rover world: 6 states, two terminal states (1 and 6) with rewards 100 and 40, all other states give reward 0.

TermMeaning in the Mars rover example
State (s)Which of the 6 positions the rover currently occupies
Action (a)Move left, or move right
Reward (R)100 for reaching state 1, 40 for reaching state 6, 0 everywhere else
Terminal statesStates 1 and 6 — once the rover arrives there, the process ends
Note the asymmetry: state 1's reward (100) is larger than state 6's reward (40) — so all else being equal, reaching state 1 is the more valuable outcome. But state 6 might be closer, meaning it can be reached in fewer steps. This tension between "which outcome is bigger" and "which outcome is closer" is exactly what the return (Section 4) is built to weigh.

3. The goal of reinforcement learning

Find a policy π that tells you what action (a = π(s)) to take in every state s, so as to maximize the return.

This single sentence is the goal of everything in this week's material. Two pieces are still undefined here — "return" and "policy" — and the rest of this file builds up exactly what they mean.

4. The return: rewarding now vs. later

If the rover just collected rewards over time, you could evaluate an approach by adding them all up. But rewards received sooner are generally treated as more valuable than the same-sized reward received later — so the rewards are added up with each one multiplied by a shrinking weight the further into the future it is.

Return  =  R1 + γR2 + γ²R3 + γ³R4 + ⋯   (until a terminal state)

Here R1, R2, R3, ... are the rewards received at each step going forward from wherever you currently are, and γ (gamma) is the discount factor — a number slightly less than 1 that shrinks the weight given to rewards the further away in time they are.

Analogy: this is exactly like the time-value of money — a dollar today is worth more to you than a dollar a year from now, so a financial return calculation discounts future dollars by some interest-rate-like factor. The discount factor γ plays that same role here: a reward of 100 four steps from now is worth less right now than a reward of 100 immediately.

5. The discount factor, gamma

γ is a number close to 1 (common choices in the lecture: 0.9, 0.99, 0.999, or for the simplified example, 0.5) that determines how strongly future rewards are discounted relative to immediate ones.

γ valueEffect
Close to 1 (e.g. 0.999)The agent is patient — a reward far in the future still counts almost as much as an immediate one
Smaller (e.g. 0.5)The agent is impatient — rewards lose value quickly the further away they are, so the agent strongly prefers quick payoffs
Why this matters practically: γ isn't just a mathematical convenience — it encodes how "impatient" the agent's behavior will be. A financial application (e.g. an RL agent managing investments) might use a γ tied to a real interest rate. A robotics application often uses γ very close to 1 (like 0.999) because delaying the reward by a handful of time steps shouldn't meaningfully change how good an outcome is considered.

6. Worked examples: how actions change the return

The return is not a fixed property of a state — it depends entirely on the sequence of actions taken from that point onward. The lecture material makes this concrete with the Mars rover using γ = 0.5.

Example A — always move left from state 4

Rewards received going forward: 0 (state 3), 0 (state 2), 100 (state 1).

Return = 0 + (0.5)(0) + (0.5)²(0) + (0.5)³(100) = 0.125 × 100 = 12.5

Example B — always move right from state 4

Rewards received going forward: 0 (state 5), 40 (state 6).

Return = 0 + (0.5)²(40) = 10
Reading the "Example of Return" table: the slide shows the return computed at every state, assuming the rover always moves left thereafter: state 2's return is 50, state 3's is 25, state 4's is 12.5, state 5's is 6.25 — each one is exactly half the return of the state before it, because each extra step away from the reward multiplies by another factor of γ = 0.5. This is a useful pattern to notice: moving one step further from a reward, under a fixed discount factor, always scales the return down by exactly γ.

Example C — different actions from different states

The lecture also shows a case where the rover moves right from states 2 and 3, but left from state 4 — i.e., the action taken depends on which state the rover is in, not a single fixed direction. This is the natural lead-in to the idea of a policy (Section 7): the "always left" and "always right" cases above are just two particular (very simple) policies among many possible ones.

Common point of confusion: the reward for a step (Rt) and the return are not the same thing. The reward is what you get at one specific step. The return is the discounted sum of all rewards from now until the terminal state. A single 0-reward step can still be part of a path with a large overall return, if a big reward is coming up soon after.

7. The policy: a strategy for every state

π(s) = a

A policy π is a function that maps every state s to the action a you should take when you're in that state. It's the complete strategy — not just what to do right now, but what to do in every situation you might find yourself in.

A policy assigns one action to every non-terminal state — here, left from states 2, 3, 4, and right from state 5.

1π(2) = ←, π(3) = ←, π(4) = ←, π(5) = → is one example policy shown in the lecture — states closer to the left reward head left, the one state closer to the right reward heads right.
2Different policies are possible for the same world — "always left," "always right," and mixed strategies are all valid policies; they just achieve different returns.
Analogy: a policy is like a complete rulebook, not a single instruction. "If it's raining, take an umbrella; if it's sunny, wear sunglasses" is a policy — it specifies what to do in every situation you might encounter, decided in advance, rather than a one-off choice made in the moment.
Why the goal is phrased in terms of a policy, not a single action: the goal stated in Section 3 — find π that maximizes the return — is really the entire aim of reinforcement learning. Every algorithm in this week's material is, in some form, a method for discovering a good π.

8. The Markov Decision Process (MDP)

The formal name for this whole setup — an agent, a set of states, actions, rewards, and a discount factor — is a Markov Decision Process.

The agent-environment loop: the agent observes a state and reward, chooses an action according to its policy π, and the environment responds with a new state and reward — repeating indefinitely (or until a terminal state).

Why "Markov": the name refers to the Markov property — the idea that the future only depends on the current state, not on the full history of how the agent got there. Once you know the rover is in state 4, it doesn't matter whether it arrived there from state 3 or state 5 — the future unfolds the same way either way. This is what makes the framework tractable: the agent never needs to remember its whole past, only where it currently is.
Going further (optional): the lecture introduces the MDP by name but doesn't derive its formal mathematical definition (the tuple of states, actions, transition probabilities, rewards, and discount factor). If you want the fuller formal treatment, Sutton & Barto's Reinforcement Learning: An Introduction (freely available online, the standard reference text in the field) covers MDPs rigorously in its early chapters — useful background, though not required to follow this course.

9. Comparing RL problems: Mars rover vs. helicopter vs. chess

The same five ingredients — states, actions, rewards, discount factor, return — describe wildly different problems. Seeing them lined up side by side is meant to show that the framework is general, even though each application fills it in very differently.

Mars roverAutonomous helicopterChess

ActionsMove left / move rightHow to move the control stickAny legal move
Rewards100, 0, or 40+1 for flying well, −1000 for crashing+1 for winning, 0 for a draw, −1 for losing
Discount factor γ0.5 (in this simplified example)0.990.995
ReturnR1 + γR2 + γ²R3 + ⋯R1 + γR2 + γ²R3 + ⋯R1 + γR2 + γ²R3 + ⋯
GoalFind π(s) = aFind π(s) = aFind π(s) = a
Why look at these together: notice that the form of the return and the form of the goal (find π(s) = a) are identical across all three — only the specific states, actions, rewards, and γ change. This is the payoff of having a general framework: the same algorithms (introduced in the parts of the week that follow) can, in principle, be applied to a tiny 6-state toy problem and to a task as complex as chess, just by plugging in a different state space, action space, and reward structure.
Notice the discount factors get closer to 1 as the task gets more delayed-consequence-heavy: the helicopter (0.99) and chess (0.995) both use γ much closer to 1 than the toy rover example (0.5). This tracks with Section 5's point — tasks where a decision now might only pay off (or backfire) many steps later need a patient agent that doesn't discount those future consequences away too quickly.

10. What's coming next

This week's material continues directly into the state-action value function (commonly written Q(s, a)) — the idea of Q(s,a) as "the return you'd get if you started in state s, took action a once, and then behaved optimally after that," and how the best possible action in a state is the one that maximizes Q(s,a).
