Week 1 — Introduction & Linear Regression with One Variable

1. What Is Machine Learning?

The big idea before any math

Machine learning is the practice of getting a computer to find patterns in data and use those patterns to make predictions — without you writing explicit rules. Instead of programming "if X then Y," you show the computer many examples of X and Y, and it figures out the rule itself.

Analogy — Imagine teaching a child to recognize dogs. You don't give them a checklist ("four legs, fur, a tail..."). You just show them hundreds of pictures labeled "dog" or "not dog," and eventually they generalize the pattern on their own. That's supervised learning.

There are two main flavors covered across this specialization:

Supervised learning — you have input data (x) paired with the correct output (y), and the algorithm learns the mapping from x to y. This is what Course 1 and most of Course 2 cover. It splits into:

• Regression — predicting a number from an infinite range of possible outputs (e.g., house price).
• Classification — predicting one of a small, finite set of categories (e.g., malignant vs. benign).

Unsupervised learning — you only have input data, with no labeled "correct answers," and the algorithm finds structure on its own (e.g., grouping similar customers together). This is Course 3's territory.

2. Linear Regression with One Variable

Fitting a straight line through data

Linear regression is the simplest supervised learning algorithm: given a scatter of (x, y) points, find the straight line that best represents the trend. Once you have that line, you can plug in a new x and predict its y.

Analogy — Imagine plotting house size (x) against house price (y) for houses that have already sold. The dots don't form a perfect line, but they trend upward. Linear regression finds the single straight line that best "summarizes" that trend, so you can estimate the price of a house whose size you know but whose price you don't.

Formally, the model is:

fw,b(x) = w·x + b

Here w (weight) controls the slope of the line, and b (bias) controls where it crosses the y-axis. "Training" the model just means finding the values of w and b that make the line fit the data best.

Each dot is a house that already sold (its real size and real price). The teal line is the model's best guess at the underlying trend — that's what "fitting" a model means.

3. The Cost Function

How do we measure "how good" a line is?

To find the best w and b, we first need a way to score how bad a given line is. The cost function does this by measuring the average squared distance between the line's predictions and the actual data points — this is called squared error cost.

J(w,b) = (1/2m) · Σ (fw,b(x(i)) − y(i))²

Breaking this down piece by piece:

• f(x⁽ⁱ⁾) − y⁽ⁱ⁾ is the error for one example — how far off the prediction was.
• Squaring it makes errors always positive (so overshooting and undershooting don't cancel out) and punishes big errors more than small ones.
• Summing over all m training examples and dividing by 2m gives the average squared error (the 2 is just there to make the calculus cleaner later — it disappears when we take derivatives).

Analogy — Think of J(w,b) as a "wrongness score." A high score means the line is a bad fit; a low score (ideally zero) means the line passes almost exactly through the data. Training a model is nothing more than searching for the w and b that make this wrongness score as small as possible.
Key insight: J(w,b) is a function of the parameters w and b — not of x. If you plot J against different values of w (holding b fixed), you get a bowl shape. The bottom of the bowl is the best possible w.

4. Gradient Descent

Finding the bottom of the bowl automatically

Now that we can score any (w, b) pair, we need a way to search for the best one without trying every possibility. Gradient descent is an iterative algorithm that starts at some random point on the cost "bowl" and repeatedly takes small steps downhill until it reaches (or gets very close to) the bottom.

Analogy — Imagine standing on a hill in thick fog — you can't see the valley, but you can feel which direction is downhill under your feet. You take a step that direction, feel again, step again, and eventually reach the bottom. That's exactly what gradient descent does mathematically.

The update rule, repeated until convergence:

w := w − α · (∂J/∂w)     b := b − α · (∂J/∂b)

• ∂J/∂w is the derivative (slope) of the cost function with respect to w — it tells you which direction is "uphill," so subtracting it moves you downhill.
• α (alpha) is the learning rate — how big a step you take each time.
• Both w and b must be updated simultaneously (using the old values of both to compute both new values), not one after another.

Why the learning rate matters: too small an α and training crawls forever; too large an α and you can overshoot the minimum and even diverge (the cost gets worse, not better). Picking a good α is mostly trial and error — try values like 0.001, 0.01, 0.1, 1 and watch how the cost behaves.

Notice the steps naturally get smaller as you approach the minimum — that's because the slope itself flattens out near the bottom, so even a fixed α produces smaller updates automatically. This is why gradient descent doesn't need a shrinking learning rate to converge nicely.

Week 2 — Multiple Linear Regression & Practical Tips

1. Multiple Linear Regression

Using more than one feature to predict

Real predictions rarely depend on just one number. A house's price depends on size, number of bedrooms, age, location, and more. Multiple linear regression extends the model to use several input features at once:

fw,b(x) = w1x1 + w2x2 + ... + wnxn + b

Each feature xj gets its own weight wj, representing how much that feature influences the prediction. This is written more compactly using vectors: f(x) = w·x + b, where w and x are both vectors (lists of numbers), and w·x is their dot product.

Analogy — Think of estimating a used car's price. You wouldn't just look at mileage — you'd weigh mileage, age, brand, and condition together. Each factor gets its own "importance weight," and the final price estimate combines all of them.

2. Vectorization

Why NumPy is fast

When you have many features and many training examples, looping over them one at a time in Python is slow. Vectorization means expressing the computation as operations on entire arrays at once (using NumPy), letting the hardware compute many multiplications in parallel instead of one after another.

Analogy — It's the difference between one person hand-stitching 1,000 shirts sequentially versus 1,000 sewing machines each stitching one shirt simultaneously. Same total work, dramatically less wall-clock time.

In code, np.dot(w, x) + b replaces a manual for-loop and runs far faster, especially on large datasets — this speed-up is essential once you move to real-world data sizes.

3. Feature Scaling

Making gradient descent converge faster

If one feature ranges from 0–5 and another ranges from 0–2000 (e.g., number of bedrooms vs. house size in square feet), gradient descent struggles: the cost function becomes a very elongated, skewed bowl, and it zig-zags slowly toward the minimum instead of heading straight there.

Analogy — Imagine that "bowl" is actually shaped like a long, narrow canyon instead of a round basin. Rolling a ball down it bounces it back and forth across the narrow walls rather than smoothly toward the bottom. Feature scaling reshapes the canyon back into a round bowl so descent goes straight to the minimum.

Common techniques:

• Mean normalization: rescale each feature to roughly range from -1 to 1 by subtracting the mean and dividing by the range.
• Z-score normalization: subtract the mean and divide by the standard deviation, so each feature has mean 0 and roughly unit variance. This is the most commonly used method in practice.

Left: elongated contours cause zig-zagging. Right: round contours let gradient descent head straight to the minimum.

4. Checking Gradient Descent for Convergence & Choosing the Learning Rate

Is training actually working?

Plot the cost J against the number of iterations (a learning curve). If it's working correctly, J should decrease after every single iteration and eventually flatten out. If J ever increases, the learning rate is almost certainly too large.

Practical tip: try a range of learning rates on a log-ish scale — 0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1 — and pick the largest one that still reliably decreases the cost every iteration.

5. Feature Engineering & Polynomial Regression

Giving the model better raw material

Sometimes the best predictor isn't one of your original features but a combination of them. E.g., if you have a house's frontage and depth, their product (frontage × depth = area) is often more predictive than either alone. Designing such new features by hand is called feature engineering.

This same idea lets linear regression fit curves, not just straight lines: by adding features like x² and x³, the model f(x) = w₁x + w₂x² + w₃x³ + b is still "linear" in the weights, but produces a curved fit — this is polynomial regression. The catch: when features like x³ are used, feature scaling becomes even more critical, since x³ grows in scale extremely fast.

Week 3 — Classification

1. Why Linear Regression Fails at Classification

Setting up the problem

Classification problems have outputs that are categories, not continuous numbers — the classic example is a tumor being malignant (1) or benign (0). If you tried to fit a straight line to 0/1 labeled data, the line would predict values like 1.4 or -0.3, which don't mean anything as a category, and a single outlier point can badly skew where the line sits — shifting your decision threshold in the wrong direction. We need a model whose output is always squeezed between 0 and 1, interpretable as a probability.

2. Logistic Regression & the Sigmoid Function

Squeezing outputs into probabilities

Logistic regression solves this by first computing the usual linear combination z = w·x + b, then passing z through the sigmoid function, which maps any real number into the range (0, 1):

g(z) = 1 / (1 + e−z)     fw,b(x) = g(w·x + b)

The output f(x) is interpreted directly as "the probability that y = 1, given input x." For example, if f(x) = 0.8, the model believes there's an 80% chance this example belongs to class 1.

Note the characteristic S-curve: far-negative z gives probabilities near 0, far-positive z gives probabilities near 1, and z = 0 always gives exactly 0.5.

3. The Decision Boundary

Turning a probability into a yes/no decision

To make an actual classification, you pick a threshold — typically 0.5. If f(x) ≥ 0.5, predict class 1; otherwise predict class 0. Since g(z) ≥ 0.5 exactly when z ≥ 0, this means the model predicts class 1 whenever w·x + b ≥ 0.

The line (or curve, if using polynomial features) where w·x + b = 0 exactly is called the decision boundary — it's the dividing line the model draws between the two classes. Everything on one side is predicted 0; everything on the other side is predicted 1.

Analogy — Picture the decision boundary as a fence drawn through a scatter of red and blue dots. The model's whole job during training is to find where to put that fence so it separates the two colors as cleanly as possible. Non-linear features (like x² terms) let that fence bend into a curve or even a closed loop instead of just a straight line.

4. The Logistic Cost Function

Why squared error doesn't work here

If you plugged the sigmoid into the squared-error cost function from linear regression, the resulting J(w,b) would be "non-convex" — bumpy, with lots of local dips that gradient descent could get stuck in. Instead, logistic regression uses log loss:

Loss = −y·log(f(x)) − (1−y)·log(1−f(x))

This looks intimidating, but it's actually two simple cases in disguise: when the true label y = 1, only the first term survives, and it heavily penalizes the model for predicting a probability close to 0 (being confidently wrong). When y = 0, only the second term survives, and it heavily penalizes predicting a probability close to 1. The average of this loss over all training examples gives a cost function that is nicely bowl-shaped (convex), so gradient descent works reliably again. In fact, the gradient descent update rule ends up looking algebraically identical to linear regression's — only the definition of f(x) has changed (now including the sigmoid).

5. The Problem of Overfitting

When a model memorizes instead of learning

A model can go wrong in two opposite directions:

• Underfitting (high bias): the model is too simple to capture the pattern in the data — e.g., fitting a straight line to clearly curved data. It performs poorly even on the training data itself.
• Overfitting (high variance): the model is so flexible (often from too many features or too high a polynomial degree) that it bends itself to fit every quirk and noise point in the training data. It scores nearly perfectly on training data but generalizes terribly to new, unseen examples.

The overfit curve snakes through every single point perfectly — but ask it to predict a brand-new x value and it will likely be wildly wrong, because it learned the noise, not the trend.

6. Addressing Overfitting: Regularization

Keeping the model humble

Three main tools fight overfitting:

• Collect more training data — with enough examples, even a flexible model can't overfit to noise, because the noise averages out.
• Use fewer features — a simpler model has less freedom to contort itself around noise.
• Regularization — keep all the features, but discourage the weights from growing too large, which softens the model's tendency to overreact to any single feature.

Regularization works by adding a penalty term to the cost function that grows with the size of the weights:

J(w,b) = (1/2m)Σ(f(x⁽ⁱ⁾)−y⁽ⁱ⁾)²  +  (λ/2m)Σwj²

The new term (λ/2m)Σwj² grows whenever any weight gets large, so gradient descent is now pulled in two directions: fit the data well, and keep the weights small. The regularization parameter λ (lambda) controls the balance:

• λ = 0 → no regularization at all (risk of overfitting).
• λ too large → the model is forced to keep weights near zero, effectively flattening the model back into underfitting.
• A well-chosen λ sits in the sweet spot between the two.

Note: by convention, the bias term b is not regularized — only the weights wj are penalized. This same regularization idea (add a λ-weighted penalty term) applies identically to logistic regression's cost function too.
