1. Why Linear Regression Fails for Classification

Classification problems ask a yes/no question: is this tumor malignant? Is this email spam? The target y only takes discrete values — in the binary case, y ∈ {0, 1}. If you try to fit a straight line (linear regression) to data like this, two things go wrong:

  • The line's output is unbounded — it can spit out values like -3.2 or 7.8, which make no sense as "is this malignant?"
  • A single outlier far along the x-axis can drag the whole line, shifting the 0.5-crossing point and changing predictions for points that didn't even move.
Why this matters This is the entire motivation for logistic regression: we need a model whose output is always squeezed between 0 and 1, so it can be read as a probability, and whose decision doesn't get distorted by examples far from the boundary.

2. The Logistic Regression Model

Logistic regression is built in two steps, and this two-step structure is the single most important thing to internalize this week — everything else (sigmoid, cost, decision boundary) is a consequence of it.

1Compute a linear combination z

Step 1 — same linear function as linear regression z = w · x + b

This is exactly the linear regression formula you already know. w is a vector of weights (one per feature), x is the feature vector, and b is the bias. On its own, z can be any real number.

2Squash z into a probability with the sigmoid

Step 2 — pass z through the sigmoid function g fw,b(x) = g(z) = g(w · x + b) = 1 / (1 + e-(w·x+b))
Why this exists Linear regression gives you an unbounded number. Classification needs a bounded probability. The sigmoid is the "adapter" that converts one into the other without throwing away the information in z — it just reshapes the number line (-∞, ∞) onto the interval (0, 1), preserving order: bigger z always means a probability closer to 1.
Analogy Think of z = w·x + b as a "raw score" — like a exam score that could theoretically be any number, positive or negative, depending on how the weights combine the features. The sigmoid function is a grading curve that squeezes any raw score into a percentage between 0% and 100%, with very negative scores mapped near 0% and very positive scores mapped near 100%.

3. The Sigmoid Function

Sigmoid / logistic function g(z) = 1 / (1 + e-z)
Behavior of zWhat happens to e-zResult: g(z)
z → very large positive (e.g. 100)e-z → tiny number ≈ 0g(z) → 1 / (1 + 0) ≈ 1
z → very large negative (e.g. -100)e-z → huge numberg(z) → 1 / huge ≈ 0
z = 0e0 = 1g(z) = 1 / (1+1) = 0.5

This gives the sigmoid its characteristic S-shape: it starts near 0 for very negative z, rises smoothly, and flattens out near 1 for very positive z, always crossing exactly through (0, 0.5).

Why this matters The crossing point at z=0, g=0.5 is not a coincidence — it's exactly what creates the decision boundary later. Whatever makes z = 0 is the boundary between the model leaning toward class 1 and leaning toward class 0.

4. Lab Walkthrough — Sigmoid Function

C1_W3_Lab02_Sigmoid_function_Soln.ipynb

Goal

Implement the sigmoid function in NumPy and see it applied to real tumor-size data.

Core code

def sigmoid(z):
    """
    Compute the sigmoid of z

    Args:
        z (ndarray): A scalar, numpy array of any size.
    Returns:
        g (ndarray): sigmoid(z), with the same shape as z
    """
    g = 1 / (1 + np.exp(-z))
    return g
Why np.exp matters here np.exp(z) works elementwise, whether z is a single scalar or a full NumPy array — so this one function correctly handles both a single prediction and a whole batch of predictions (e.g. z_tmp = np.arange(-10, 11)) without writing a loop. This is why the lab explicitly tests both a single value and an array as input.

What the lab shows you

  • Plotting sigmoid(z) for z from -10 to 10 reproduces the S-curve, flattening near 0 and 1, crossing 0.5 at z=0.
  • The full logistic regression model is then just f(x) = sigmoid(w·x + b), applied to the tumor-size dataset (x_train, y_train).
  • The lab includes an interactive widget (plt_one_addpt_onclick) that lets you click "Run Logistic Regression" and watch the sigmoid curve fit the data, then apply a 0.5 threshold to turn the probability into a hard 0/1 prediction — this is your first hands-on preview of the decision boundary concept in Section 6.

5. Interpreting the Output as a Probability

The output f(x) of logistic regression is best understood as the model's estimate of the probability that y = 1, given input x.

Formal notation you'll see in papers f(x) = P(y = 1 | x ; w, b)

Read this as: "the probability that y equals 1, given x, using parameters w and b." The semicolon separates the input variable from the parameters that control the computation — you don't need to memorize this notation, just recognize it.

Since y can only be 0 or 1, the two probabilities must sum to 1:

P(y=0 | x) + P(y=1 | x) = 1

Example: if the model outputs f(x) = 0.7, it's saying there's a 70% chance the tumor is malignant (y=1) and therefore a 30% chance it's benign (y=0).

Common confusion to avoid f(x) = 0.7 is not the prediction itself. The true label y is always exactly 0 or 1 — never 0.7. The 0.7 is the model's confidence, which you then convert into a hard 0/1 decision using a threshold (covered next in Decision Boundary).

6. Decision Boundary

From probability to a hard decision

To turn f(x) into an actual 0/1 prediction, pick a threshold — commonly 0.5:

If f(x) ≥ 0.5 → predict ŷ = 1
If f(x) < 0.5 → predict ŷ = 0

Tracing the threshold back to z

Because f(x) = g(z), and we know g(z) ≥ 0.5 exactly when z ≥ 0, the condition collapses to a much simpler one:

f(x) ≥ 0.5  ⟺  g(z) ≥ 0.5  ⟺  z ≥ 0  ⟺  w·x + b ≥ 0
Why this matters This means you never actually need to compute the sigmoid to know the predicted class — you only need the sign of w·x + b. This is a huge simplification: the geometry of classification reduces to "which side of a line (or curve) is this point on?"

The decision boundary itself

The decision boundary is the set of points where the model is exactly neutral — where z = w·x + b = 0. This line (or curve) separates the region predicted as class 1 from the region predicted as class 0.

Linear decision boundary

Example: w₁=1, w₂=1, b=-3

Boundary: x₁ + x₂ - 3 = 0 → the line x₁ + x₂ = 3

Right of the line → predict 1. Left of the line → predict 0.

Non-linear decision boundary

Using polynomial features: z = x₁² + x₂² - 1

Boundary: x₁² + x₂² = 1 → a circle

Outside circle → predict 1. Inside circle → predict 0.

Analogy Imagine the decision boundary as the edge of a shadow cast by the model. Everything the shadow falls on is "class 0"; everything lit up is "class 1." With only raw features (x₁, x₂, ...), that shadow's edge can only be a straight line — a flat wall. Add polynomial features (x₁², x₁x₂, ...) and the "wall" can bend into circles, ellipses, or wavy shapes, letting the model fit far more complex data patterns.
Key limitation to remember With only the raw features (no polynomial terms), the decision boundary for logistic regression is always linear — a straight line, plane, or hyperplane. Curved boundaries only appear once you engineer polynomial features (x₁², x₁x₂, x₂², ...) — this is the same feature-engineering idea from linear regression, reused here.

8. Why the Squared Error Cost Function Fails Here

For linear regression, the cost function was the mean squared error, and plotting it against the parameters gave a smooth, bowl-shaped (convex) surface — gradient descent could always slide downhill to the single global minimum.

If you plug the logistic regression model (with the sigmoid inside it) into that same squared-error formula, the resulting cost surface becomes non-convex — it's wiggly, with many local dips ("local minima").

Why this is a real problem Gradient descent on a non-convex surface can get stuck in a local minimum that isn't the best possible set of parameters, and where it ends up depends on where it started. There's no guarantee of finding the true best-fitting model.
Why this matters This is the entire reason logistic regression needs its own, differently-shaped cost function instead of reusing linear regression's. The new cost function (built from log-loss, next section) is specifically constructed to stay convex even with the sigmoid inside it — restoring the "bowl shape" guarantee that gradient descent depends on.

9. Loss vs. Cost — and the New Loss Function

Terminology, precisely Loss = error on one single training example.
Cost = the average loss across the entire training set. Cost is a function of the loss; loss is a function of one prediction.

The two-case loss function

Loss for one example (x⁽ⁱ⁾, y⁽ⁱ⁾) L(f(x⁽ⁱ⁾), y⁽ⁱ⁾) =  {  −log(f(x⁽ⁱ⁾))     if y⁽ⁱ⁾ = 1
    {  −log(1 − f(x⁽ⁱ⁾))  if y⁽ⁱ⁾ = 0

Case y = 1: loss = −log(f(x))

  • If the model predicts close to 1 (confidently, correctly right) → −log(≈1) ≈ 0 → tiny loss.
  • If the model predicts close to 0 (confidently, badly wrong) → −log(≈0) → ∞ → loss explodes toward infinity.

Case y = 0: loss = −log(1 − f(x))

  • If the model predicts close to 0 (confidently, correctly right) → tiny loss.
  • If the model predicts close to 1 (confidently, badly wrong) → loss explodes toward infinity.
Why log-loss specifically (not squared error) Two reasons converge here: (1) mathematically, this shape keeps the overall cost function convex when combined with the sigmoid, unlike squared error. (2) Behaviorally, it punishes confident wrong answers extremely harshly — a model that says "99.9% sure it's benign" when it's actually malignant gets an enormous loss, appropriately, because confidently wrong is far more dangerous than cautiously wrong. Squared error would only mildly penalize that same mistake.
Analogy Log-loss is like a strict teacher grading true/false answers with a confession requirement: if you're right, barely any penalty, no matter how confident you were. But if you're confidently wrong ("I'm 99% sure!") and the correct answer was the opposite, the penalty rockets upward — approaching infinite "detention time" the more confidently wrong you were. This forces the model to be humble about its confidence unless the data really backs it up.

The full cost function (average loss)

Cost J(w,b) — average loss over all m examples J(w,b) = (1/m) Σi=1m L(f(x⁽ⁱ⁾), y⁽ⁱ⁾)

Because the underlying loss function is chosen carefully (log-loss, not squared error), this average — plotted against w and b — comes out convex: a single bowl shape with one global minimum, which gradient descent can reliably find.

10. The Simplified (Combined) Loss Function

Writing the loss as two separate cases (one for y=1, one for y=0) is correct but awkward to implement — it needs an if/else. Because y can only be exactly 0 or 1, both cases can be fused into a single algebraic line:

Simplified loss — one formula, no branching L(f(x), y) = −y·log(f(x)) − (1−y)·log(1−f(x))

Why this single line is mathematically identical to the two-case version

When y = 1When y = 0
(1−y) = 0, so the second term vanishes:
L = −1·log(f(x)) − 0 = −log(f(x))
→ matches the y=1 case exactly. 		y = 0, so the first term vanishes:
L = −0 − 1·log(1−f(x)) = −log(1−f(x))
→ matches the y=0 case exactly.
Why this matters This isn't just a coding convenience — it's what makes gradient descent's math tractable later. A single differentiable formula (rather than a piecewise one) is far easier to take derivatives of when deriving the gradient descent update rules for w and b, which is exactly what the course does in the very next lecture.

The simplified cost function

Plug the combined loss into the average-cost formula and pull the negative sign outside the sum:

This is THE logistic regression cost function used almost everywhere J(w,b) = −(1/m) Σi=1m [ y⁽ⁱ⁾·log(f(x⁽ⁱ⁾)) + (1−y⁽ⁱ⁾)·log(1−f(x⁽ⁱ⁾)) ]
Where this formula comes from (just so you've seen it) This exact cost function isn't arbitrary — it falls directly out of a statistics technique called Maximum Likelihood Estimation (MLE): choosing the parameters that make the observed labels as probable as possible under the model. You don't need to derive MLE for this course, but knowing it exists explains why "everyone" uses this specific cost function rather than inventing their own.

11. Deep Dive — Lab 5: Cost Function for Logistic Regression

This is the most important lab of the week for connecting theory to code — it takes the exact formula from Section 10 and turns it into a working, testable Python function, then uses it to numerically prove that one decision boundary really is better than another.

1. The dataset (same one from Lab 3)

X_train = np.array([[0.5, 1.5], [1,1], [1.5, 0.5], [3, 0.5], [2, 2], [1, 2.5]])  #(m,n)
y_train = np.array([0, 0, 0, 1, 1, 1])                                          #(m,)

6 examples, 2 features each. The shape comment (m,n) is a habit worth adopting yourself: m = number of examples (rows), n = number of features (columns). Always sanity-check array shapes this way before writing loops over them.

2. The cost function implementation, line by line

def compute_cost_logistic(X, y, w, b):
    """
    Computes cost

    Args:
      X (ndarray (m,n)): Data, m examples with n features
      y (ndarray (m,)) : target values
      w (ndarray (n,)) : model parameters
      b (scalar)       : model parameter

    Returns:
      cost (scalar): cost
    """
    m = X.shape[0]
    cost = 0.0
    for i in range(m):
        z_i = np.dot(X[i],w) + b
        f_wb_i = sigmoid(z_i)
        cost +=  -y[i]*np.log(f_wb_i) - (1-y[i])*np.log(1-f_wb_i)

    cost = cost / m
    return cost
Code lineMaps to which piece of the math
m = X.shape[0]The number of training examples, m, used as the divisor in the averaging step
for i in range(m):The summation Σi=1m — looping over every training example
z_i = np.dot(X[i], w) + bz⁽ⁱ⁾ = w · x⁽ⁱ⁾ + b — Step 1 of the logistic regression model, for example i
f_wb_i = sigmoid(z_i)f(x⁽ⁱ⁾) = g(z⁽ⁱ⁾) — Step 2, applying the sigmoid from Lab 2
cost += -y[i]*np.log(f_wb_i) - (1-y[i])*np.log(1-f_wb_i)The simplified per-example loss term from Section 10, accumulated into the running total
cost = cost / mThe (1/m) outside the summation — converting total loss into average loss (cost)
Implementation detail worth noticing This is the "unvectorized" version — a plain Python for loop over examples, calling np.dot per row. It's written this way for clarity, so each line maps directly onto one piece of the formula. In practice, for speed, this is later rewritten as a fully vectorized NumPy computation (no Python-level loop) — but understanding this loop version first is what makes the vectorized version make sense later, so don't skip it.

4. The real payoff — comparing two decision boundaries numerically

Recall from Lab 3 that b = -3, w = [1,1] gave a decision boundary x₀ + x₁ = 3 that visually separated the classes well. This lab now asks: what if we'd instead picked b = -4 (boundary x₀ + x₁ = 4)? Is it actually worse, or does it just look worse?

w_array1 = np.array([1,1]); b_1 = -3
w_array2 = np.array([1,1]); b_2 = -4

print("Cost for b = -3 : ", compute_cost_logistic(X_train, y_train, w_array1, b_1))
print("Cost for b = -4 : ", compute_cost_logistic(X_train, y_train, w_array2, b_2))

# Cost for b = -3 :  0.3668667864055175
# Cost for b = -4 :  0.5036808636748461
Why this result matters — this is the whole point of the lab The cost function gives a quantitative, objective number confirming what your eyes already suspected from the plot: b = -3 (cost ≈ 0.367) is a genuinely better fit than b = -4 (cost ≈ 0.504). Higher cost = worse fit. This is exactly the signal that gradient descent will use in the next lecture: it will nudge w and b in whichever direction makes this cost number go down, iteration by iteration, until it settles near the true minimum.

12. Summary & Key Takeaways

The full pipeline, end to end

  1. Model: z = w·x + b, then f(x) = sigmoid(z) = 1/(1+e⁻ᶻ) → outputs a probability between 0 and 1.
  2. Prediction: threshold at 0.5 → equivalent to checking whether z ≥ 0, i.e. whether w·x + b ≥ 0.
  3. Decision boundary: the curve/line where z = 0 exactly — linear with raw features, curved with polynomial features.
  4. Why not squared error: produces a non-convex cost surface with logistic regression → gradient descent can get stuck.
  5. Loss (per example): −y·log(f(x)) − (1−y)·log(1−f(x)) — heavily penalizes confident wrong predictions; stays convex.
  6. Cost (whole dataset): the average of all per-example losses, J(w,b) — this is what gradient descent will minimize next.
  7. Lab 5's proof: plugging in two different b values shows numerically that the visually-better boundary really does have lower cost.
The one idea to hold onto above all others Every piece this week exists to answer one question: "given a set of parameters, how do I get a single number that tells me how good they are, that I can then improve?" The sigmoid makes the model's output meaningful (a probability); the log-loss cost function makes that "goodness score" mathematically well-behaved (convex) so that gradient descent — coming next — can actually improve it reliably.
