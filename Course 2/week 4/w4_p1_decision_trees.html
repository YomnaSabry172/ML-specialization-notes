1. What a decision tree actually is

The running example this week is a cat adoption center. You have 10 animals, each described by three categorical features — ear shape (pointy/floppy), face shape (round/not round), and whiskers (present/absent) — and a binary label: cat or not cat. This is binary classification with categorical inputs.

A decision tree is a flowchart-like structure that makes a prediction by asking a sequence of yes/no-style questions about the features:

  • The root node is the topmost node — the first question asked, applied to every example.
  • Decision nodes (the ovals below it) each look at one feature and route the example left or right depending on its value.
  • Leaf nodes (the rectangles at the bottom) don't ask anything further — they just output a prediction.

To classify a new animal, you start at the root, answer the question posed there, follow the branch matching your example's feature value, and keep going until you land on a leaf. Whatever that leaf says, is the prediction.

Analogy: the "roots at the top, leaves at the bottom" layout feels backwards if you picture a real tree — but think of it as an indoor hanging plant instead. The roots are anchored up top (where the tree "starts" conceptually), and the leaves dangle down toward the bottom, which is exactly where you land when you're done asking questions and ready for an answer.
Why this matters: for a fixed dataset, there isn't just one possible tree — you could split on ear shape first, or whiskers first, or in a dozen other orders, and each choice produces a different tree with different accuracy on new data. The entire rest of this week is about answering one question precisely: out of all the trees you could build, how does the algorithm decide which questions to ask, and in what order, so that the result generalizes well? That's what Sections 2–5 build up to.

2. The learning process: two key decisions

Building a tree from a training set is a recursive process. Here's a concrete run-through with the cat dataset:

  1. Root node: of the three features, suppose the algorithm decides ear shape gives the best split. All 10 examples are divided: 5 with pointy ears go left, 5 with floppy ears go right.
  2. Left branch: looking only at those 5 pointy-eared examples, the algorithm picks the next best feature to split on — say, face shape. 4 round-faced examples go further left, 1 not-round example goes right.
  3. The 4 round-faced examples are all cats — 100% one class — so a leaf node is created here that always predicts "cat." Nothing more to split; splitting further would gain you nothing.
  4. The 1 remaining example is 0% cats (i.e. it's a dog), so a leaf predicting "not cat" is created there too.
  5. Right branch: back at the 5 floppy-eared examples (1 cat, 4 dogs), the algorithm splits again — say on whiskers. Present vs. absent produces two more pure groups, and two more leaves are created.

Notice this is the same basic step — "pick the best feature, split the data, recurse on each half" — applied over and over on smaller and smaller subsets. That repetition is exactly why it's called a recursive algorithm: building the left subtree and building the right subtree are literally the same sub-problem as building the whole tree, just on fewer examples.

Every time you're at a node with a mix of classes, you face two decisions:

Decision 1 — Which feature to split on?

At the root, and again at every node below it, you have to choose among the available features (ear shape, face shape, whiskers). The chosen feature should maximize purity — meaning the two resulting subsets should be as close as possible to "all cats" or "all dogs," rather than a 50/50 mix. If you had access to a (hypothetical) "has cat DNA" feature, splitting on it would send 100% of cats one way and 100% of dogs the other — perfectly pure in one step. Real features like ear shape only get you partway there, which is exactly why you need a principled way to score "how good is this split" — that's entropy and information gain, covered in Sections 3–4.

Decision 2 — When to stop splitting?

You don't split forever. Four common stopping criteria:

  • A node is 100% one class — it's already pure, so turn it into a leaf immediately.
  • Maximum depth reached — depth counts hops from the root (root = depth 0, its children = depth 1, and so on). Capping depth keeps the tree from growing unboundedly.
  • Improvement in purity is too small — if splitting further barely reduces impurity, it's not worth the added complexity.
  • Too few examples remain at a node — splitting a group of, say, 3 examples into even smaller slivers rarely helps and mostly just memorizes noise.
Why this matters: both stopping rules exist for the same underlying reason — controlling overfitting. A tree that keeps splitting until every leaf is perfectly pure on the training set will often carve out tiny, idiosyncratic regions that don't generalize — it's memorizing quirks of these 10 examples rather than learning the real pattern distinguishing cats from dogs. Keeping the tree smaller (shallower depth, fewer needless splits) trades a bit of training accuracy for much better performance on new data.
Note on how this feels: decision trees evolved as a patchwork — one researcher proposed a base version, others added stopping criteria, splitting refinements, and so on, each for their own reasons. So if the full algorithm feels like a collection of separate heuristics bolted together rather than one clean derivation, that's a fair reaction — it does work very well in practice regardless.

3. Measuring purity: entropy

To make Decision 1 (which feature to split on) objective rather than a judgment call, you need a number that captures "how mixed is this set of examples." That number is entropy, denoted H.

Define p₁ as the fraction of examples in a set that belong to the positive class (cats, label = 1). Entropy as a function of p₁:

H(p₁) = −p₁·log₂(p₁) − p₀·log₂(p₀)    where p₀ = 1 − p₁

Equivalently, written purely in terms of p₁:

H(p₁) = −p₁·log₂(p₁) − (1−p₁)·log₂(1−p₁)
Set compositionp₁H(p₁)Interpretation
3 cats, 3 dogs3/6 = 0.51.0Maximum impurity — perfectly mixed
5 cats, 1 dog5/6 ≈ 0.83≈0.65Fairly pure
6 cats, 0 dogs6/6 = 1.00Perfectly pure
2 cats, 4 dogs2/6 ≈ 0.33≈0.92Quite impure (closer to 50/50 than the 5/1 case)
0 cats, 6 dogs0/6 = 00Perfectly pure (all one class, just the other one)

Plotted against p₁, H looks like a hump: it starts at 0 (all one class), rises to a peak of 1 at p₁ = 0.5 (perfectly mixed), then falls back to 0 at p₁ = 1 (all the other class).

Why log base 2, and why 0·log(0) = 0: logs are taken base 2 purely by convention, so that the peak of the curve lands exactly at 1 — a clean, easy-to-read number. Using natural log instead would just rescale the curve vertically and still work, but the peak wouldn't be a round number anymore. Separately, when p₁ or p₀ is exactly 0, the term 0·log₂(0) is mathematically undefined (log(0) = −∞), but by convention it's defined to equal 0 for entropy purposes — which correctly gives H = 0 for a perfectly pure set, matching the intuition that a pure set has zero impurity.
Analogy: think of entropy as "how surprised would you be by the next example drawn from this set?" If the set is all cats, you're never surprised (entropy 0) — you know it'll be a cat. If it's a 50/50 mix, you have zero ability to guess ahead of time (maximum entropy, 1) — it's a coin flip.
Note: the lecture flags that entropy's formula resembles the logistic loss from the previous course, and says there's a real mathematical reason for that, but it's not something you need to dig into to use entropy for building trees. There's also an alternative impurity measure used in some libraries called the Gini criterion, which behaves similarly (0 → 1 → 0 shape) — entropy is simply the one used throughout this course for consistency.

4. Choosing a split: information gain

Entropy alone tells you how impure one set is. To choose which feature to split on, you need to compare candidate splits — and each split produces two subsets (left and right), so you need a way to combine their two entropy values into one comparable number.

Step 1 — weighted average entropy

Simply averaging the left and right entropy values isn't quite right, because a highly impure branch with many examples is worse than a highly impure branch with only a few. So the two entropies are combined as a weighted average, weighted by what fraction of examples went to each side:

wleft·H(p₁left) + wright·H(p₁right)

where wleft and wright are the fractions of the parent node's examples that went left and right respectively (they sum to 1).

Step 2 — measure the reduction, not the raw weighted entropy

Rather than using that weighted average directly, the convention is to compute how much entropy decreased relative to the parent node before splitting. This is called information gain:

Information Gain = H(p₁root) − ( wleft·H(p₁left) + wright·H(p₁right) )

Worked example at the root node (5 cats, 5 dogs, so p₁root = 0.5, H = 1) comparing all three candidate features:

Split featureLeft (p₁, H)Right (p₁, H)Weighted entropyInformation gain
Ear shape4/5 = 0.8, H≈0.721/5 = 0.2, H≈0.720.720.28
Face shape4/7≈0.57, H≈0.991/3≈0.33, H≈0.920.970.03
Whiskers3/4=0.75, H≈0.812/6≈0.33, H≈0.920.880.12

Ear shape gives the highest information gain (0.28), so it's chosen as the root split — matching the tree built in Section 2.

Why this matters: computing the reduction rather than just the raw weighted entropy isn't just cosmetic — it directly enables one of the stopping criteria from Section 2. If the best available information gain at some node is below a small threshold, that's the algorithm's signal that "splitting further isn't worth it," and it can stop and create a leaf instead. You can't express that rule cleanly without first framing the score as a gain relative to not splitting.

General formula

Information Gain = H(p₁root) − ( wleft·H(p₁left) + wright·H(p₁right) )

where p₁root, p₁left, p₁right are the fractions of positive (cat) examples in the parent node, left subset, and right subset respectively, and wleft, wright are the fractions of the parent's examples that ended up in each subset.

5. Putting it together: the recursive algorithm

The full decision tree learning algorithm, stated as a loop:

  1. Start with all training examples at the root node.
  2. Calculate information gain for every candidate feature, and pick the one with the highest gain.
  3. Split the dataset according to that feature, creating a left branch and a right branch.
  4. Keep repeating this splitting process on each new branch — recursively treating each branch as its own smaller "root node" problem — until a stopping criterion is met (100% one class, max depth reached, information gain below threshold, or too few examples left).

This is exactly what "recursive" means here: building the left subtree is the identical procedure as building the whole tree, just restricted to the subset of examples that went left. The same is true for the right subtree. The recursion bottoms out whenever a stopping criterion fires and a leaf gets created instead of another split.

Note: it's entirely valid for the algorithm to split on the same feature more than once in different branches (e.g. face shape appearing under both the pointy-ear and floppy-ear branches) if that's what the information-gain comparison favors independently in each branch — the algorithm doesn't remember or forbid reusing a feature name.

6. Features with more than two values: one-hot encoding

So far, every feature had exactly two possible values (pointy/floppy, round/not round, present/absent). What if a categorical feature can take k possible values — for example, ear shape becomes pointy, floppy, or oval (k = 3)?

One option is to let a single split create three branches instead of two. But the standard approach used here instead is one-hot encoding: replace the one k-valued feature with k new binary features, one per possible value.

For ear shape with 3 possible values, you'd create: "is ear shape pointy?", "is ear shape floppy?", "is ear shape oval?" — each is 0 or 1. For any given example, exactly one of these three new features is 1 (the "hot" one) and the rest are 0 — hence the name one-hot.

k possible categorical values → k new binary (0/1) features, exactly one of which is 1 per example
Why this matters: after one-hot encoding, every feature is back to being binary — so the exact same splitting, entropy, and information-gain machinery from Sections 3–4 applies with zero modification. One-hot encoding doesn't add new capability to the tree algorithm; it just reshapes the input so the existing algorithm's assumptions (binary-valued features) keep holding.
Note — this isn't tree-specific: one-hot encoding is a general technique for feeding categorical data into any model that expects numeric inputs, not just decision trees. The same 3 (ear shape) + 1 (face shape) + 1 (whiskers) = 5 one-hot features could equally be fed into logistic regression or a neural network to train a cat classifier.

7. Continuous-valued features

Now suppose you add a genuinely numeric feature: the animal's weight in pounds (cats tend to be lighter than dogs on average, though there's overlap). How does splitting work on a feature that isn't a small set of discrete values?

The approach: pick a threshold value t, and split examples into "weight ≤ t" (left) vs. "weight > t" (right). The algorithm needs to search over many candidate thresholds and pick whichever one yields the highest information gain — exactly the same information-gain scoring as before, just applied to a threshold-based split instead of a categorical one.

Worked example from the lecture, comparing three candidate thresholds on weight:

ThresholdSplit producedInformation gain
weight ≤ 82 cats left; 3 cats + 5 dogs right0.24
weight ≤ 94 cats (all cats) left; 1 cat + 5 dogs right0.61
weight ≤ 13(different split)0.40

Threshold 9 wins here — it produces the highest information gain of the three, and (per the worked example) also beats every other feature's information gain, so the tree would split on "weight ≤ 9" at that node.

Which thresholds to actually try: the standard convention is to sort all training examples by the feature's value, then test the midpoints between each pair of consecutive sorted values as candidate thresholds. With 10 training examples, that produces 9 candidate thresholds to evaluate — you don't need to guess at arbitrary threshold values.
Why this matters: this is the same core algorithm as Sections 4–5 — compute information gain, pick the best option — just with one extra inner loop: instead of "which feature has the best information gain," it becomes "which (feature, threshold) pair has the best information gain," since a continuous feature effectively offers many candidate splits rather than one.

8. Regression trees (optional): predicting a number

Everything so far predicted a category (cat / not cat). A regression tree generalizes decision trees to predict a continuous number instead — here, predicting an animal's weight as the target output Y (note: in this section weight is the thing being predicted, not an input feature as it was in Section 7).

What variance is, and why it replaces entropy here

Definition — variance: variance is a statistical measure of how spread out, or how widely dispersed, a set of numbers is around their average. A set of numbers that are all close together has low variance; a set of numbers spanning a wide range has high variance. Formally, for a set of values y⁽¹⁾, ..., y⁽ᵐ⁾ with mean ȳ, variance is the average of the squared deviations from the mean:
Variance = (1/m) ∑i=1m (y(i) − ȳ)²
You don't need to hand-compute this for the course — the key intuitive point is just: low variance = the numbers are clustered tightly; high variance = the numbers are scattered widely.

For classification, entropy measured impurity of class labels. For regression, there's no notion of "class label" to be pure or impure about — instead, what you want each leaf's group of examples to have in common is a similar target value. So regression trees use variance in place of entropy: a good split is one where the weights within each resulting branch are tightly clustered (low variance), rather than one where the class labels are pure.

Concretely, from the lecture's data: one candidate split produced a left branch with weights {7.2, 9.2, 8.4, 7.6, 10.2} — variance 1.47 (tightly clustered) — versus a different split's branch of {8.8, 15, 11, 18, 20} — variance 21.87 (widely spread). Lower variance means the examples in that branch agree with each other much more about what the target value should be, which is exactly what you want a leaf's prediction to be able to rely on.

Reduction in variance (the regression analogue of information gain)

Just as classification didn't use raw weighted entropy but the reduction relative to the parent (information gain), regression trees use the reduction in variance:

Reduction in Variance = Variance(root) − ( wleft·Variance(left) + wright·Variance(right) )

Worked example — root node variance (all 10 weights together) = 20.51:

Split featureLeft variance, wleftRight variance, wrightReduction in variance
Ear shape1.47, 5/1021.87, 5/108.84
Face shape27.80, 7/101.37, 3/100.64
Whiskers0.75, 4/1023.32, 6/106.22

Ear shape gives the largest reduction in variance (8.84), so it's chosen as the root split for the regression tree — the exact same "pick whichever candidate maximizes the reduction score" logic as classification, just with variance in place of entropy.

How predictions are made at the leaves

Once the tree is fully built and a new test example reaches a leaf, the predicted weight is simply the average of the training-set weights that landed in that same leaf during training. For example, a leaf containing training weights 7.2, 9.2, 7.6, and 10.2 would predict their average, 8.35 lbs, for any new animal routed to that same leaf.

Why this matters: this is the core conceptual shift from classification to regression trees — a classification leaf answers "what class is this?" by majority vote / purity, while a regression leaf answers "what value is this?" by averaging. Everything else about the tree — the recursive splitting structure, comparing candidate features, stopping criteria — carries over unchanged; only the impurity measure (variance instead of entropy) and the leaf's prediction rule (average instead of majority class) differ.
Analogy: think of variance the way you'd think about a group of people's guesses on a trivia question. If everyone in the group guessed answers clustered tightly around the true value, that group is "low variance" and you can trust their average. If their guesses are all over the place, the group is "high variance" and the average is a much shakier prediction. A regression tree is built specifically to keep sorting examples into groups whose target values agree with each other as tightly as possible.

9. Summary

ConceptRole
Root / decision / leaf nodesStructure of the tree: where questions are asked (root, decision nodes) vs. where predictions are made (leaves)
Entropy H(p₁)Measures impurity of a set for classification; 0 = pure, 1 = maximally mixed
Information gainReduction in entropy from a candidate split — the score used to choose which feature (classification) to split on
One-hot encodingConverts a k-valued categorical feature into k binary features so the standard algorithm still applies
Threshold splitsHow continuous-valued features are handled — search candidate thresholds, score each by information gain
VarianceMeasures spread of numeric target values within a set — the regression-tree analogue of entropy
Reduction in varianceThe regression-tree analogue of information gain — score used to choose splits when predicting a number
Stopping criteriaNode is pure / max depth reached / gain below threshold / too few examples — all exist to limit overfitting
Common point of confusion to avoid: entropy/information gain and variance/reduction-in-variance are not two different algorithms — they are the same recursive splitting procedure, just paired with the impurity measure appropriate to the task (categorical labels vs. numeric targets). If you understand one, you understand the structure of the other; only the formula for "how impure/spread out is this set" changes.
