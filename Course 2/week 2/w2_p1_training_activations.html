1. Step 1 — Specify how to compute the output (define the model)

Training a neural network in TensorFlow mirrors the three steps you already used for logistic regression. Step 1 is the same idea, scaled up: instead of one set of parameters w, b, you now have a set of parameters for every layer.

Logistic regression:   fw,b(x) = g(w·x + b)   where g is sigmoid

Neural network:   a[l] = g(W[l]·a[l-1] + b[l])   for every layer l

In code, this step is just declaring the architecture:

import tensorflow as tf
from tensorflow.keras import Sequential
from tensorflow.keras.layers import Dense

model = Sequential([
    Dense(units=25, activation='sigmoid'),
    Dense(units=15, activation='sigmoid'),
    Dense(units=1,  activation='sigmoid'),
])

Same architecture from Week 1 — this line of code fully specifies it, including all the W[l], b[l] parameters TensorFlow needs to track.

Why this matters: this step alone is enough to run forward propagation (inference) — it says nothing yet about how good the predictions are or how to improve them. That's what steps 2 and 3 are for.

2. Step 2 — Specify the loss and cost functions

Recall from logistic regression: the loss measures how wrong the model is on one example; the cost is the average loss over the whole training set. Neural networks use the exact same definitions — the loss is just now computed on the network's final output f(x) = a[3] instead of a plain logistic regression output.

Loss (binary classification):   L(f(x), y) = −y log(f(x)) − (1−y) log(1−f(x))

Cost:   J(W, B) = (1/m) Σi=1m L(fW,B(x(i)), y(i))

In TensorFlow this loss has a name: binary cross-entropy.

from tensorflow.keras.losses import BinaryCrossentropy

model.compile(loss=BinaryCrossentropy())
Where does "cross-entropy" come from? It's a term from statistics/information theory for exactly this loss shape. "Binary" just flags that this is a two-class problem (digit is 0 or 1).

Regression instead of classification?

If y is a continuous number rather than a class label, swap in mean squared error:

Loss:   (1/2)(f(x) − y)² 
from tensorflow.keras.losses import MeanSquaredError

model.compile(loss=MeanSquaredError())
Notation: capital W and B in J(W, B) stand for all the parameters across every layer — W[1], W[2], W[3], b[1], b[2], b[3] bundled together. That's why you sometimes see the output written fW,B(x).

3. Step 3 — Minimize the cost (gradient descent + backpropagation)

Same gradient descent update rule as before, just applied to every parameter in every layer:

Wlj ← Wlj − α · ∂J(W,B)/∂Wlj
bl ← bl − α · ∂J(W,B)/∂bl 
model.fit(X, y, epochs=100)
Why this matters: computing those partial derivatives across many stacked layers is the hard part — doing it by hand would require applying the chain rule layer by layer. The algorithm that does this automatically and efficiently is called backpropagation, and it's exactly what runs inside model.fit(). TensorFlow (and, in fact, essentially every deep learning library) implements backprop for you.
Epochs: the number of steps of gradient descent to run — a carried-over term from Course 1, not a new neural-network-specific idea.
Don't skip the "why": Andrew Ng's own framing here is worth keeping — call these library functions, but understand what's happening underneath. If training doesn't converge or behaves strangely, you can only debug it if you know what compile() and fit() are actually doing (specifying a cost function, then running gradient descent via backprop).

4. Putting it together: the full TensorFlow recipe

The same three-step recipe as logistic regression — just applied to a stack of layers instead of one.

Analogy: think of it like teaching someone to cook a new dish. Step 1 is writing down the recipe (how inputs become outputs). Step 2 is agreeing on how you'll score how close the dish is to the target dish (the loss/cost). Step 3 is the actual practice — repeatedly adjusting technique (parameters) based on that scoring, using feedback from every stage of the process (backprop propagates the "error signal" back through every layer, not just the last one).

5. Why do we need activation functions at all?

Before looking at ReLU, it's worth answering a more basic question: what breaks if every neuron just uses the linear activation g(z) = z (i.e., "no activation function")?

The collapse: a linear function of a linear function is still linear. Stack as many layers as you want — if every activation is linear, the whole network reduces to one big linear function of the input.

Worked through with a minimal 1-input, 1-hidden-unit, 1-output network:

a[1] = g(w[1]x + b[1]) = w[1]x + b[1]   (since g(z)=z)
a[2] = g(w[2]a[1] + b[2]) = w[2](w[1]x + b[1]) + b[2]
    = (w[2]w[1])x + (w[2]b[1] + b[2])
    = wx + b   (just relabeling the combined constants)

The two-layer network collapsed into a[2] = wx + b — exactly the form of plain linear regression. General case: many linear hidden layers + a linear output layer ⇒ equivalent to linear regression. Many linear hidden layers + a sigmoid output layer ⇒ equivalent to plain logistic regression. Either way, all the extra layers bought you nothing.

Why this matters: the entire appeal of a neural network is that it can represent functions far more complex than a straight line or a single logistic curve. That expressive power comes specifically from stacking non-linear activations. Without non-linearity, depth is decorative — no matter how many layers you add, you're still fitting a straight line.
Rule of thumb: never use the linear activation in hidden layers. It's fine (even necessary) at the output layer for certain problems (see below) — the risk is specifically about hidden layers, where it silently erases everything extra layers were supposed to add.

6. ReLU — an alternative to sigmoid

Motivating example: predicting "awareness" of a product from marketing spend. Modeling awareness as strictly binary (aware / not aware, via sigmoid) undersells reality — awareness plausibly ranges continuously from none to "went viral," i.e. any non-negative number, not just a value squeezed into [0, 1].

ReLU:   g(z) = max(0, z)

ReLU stands for Rectified Linear Unit — a historical name from its inventors, not a description you need to over-interpret. In practice: for z < 0, output is 0 (flat); for z ≥ 0, output is just z (a 45° line).

The three activation functions covered this week: linear (rarely used in hidden layers), sigmoid (bounded 0–1), ReLU (unbounded above, flat below zero).

Analogy: sigmoid is like a light switch with a dimmer that maxes out — good for representing "on-ness" that saturates. ReLU is more like a valve: fully closed below a threshold, then opens proportionally to pressure with no ceiling — better suited to a quantity like "how much" rather than "is it on."
Third option, "linear activation": g(z) = z. When people say a layer has "no activation function," they usually mean this — since g(z)=z just passes z straight through, it's as if there were no g at all.

7. Choosing the activation for the output layer

The choice here is driven directly by what kind of label y you're predicting — not a free style choice.

Problem typeTarget yOutput activationWhy
Binary classificationy ∈ {0, 1}SigmoidNetwork learns P(y=1 | x), same interpretation as logistic regression
Regression (either sign)y can be + or −LinearOnly linear activation can output negative values
Regression (non-negative)y ≥ 0 (e.g. house price)ReLUReLU's range is exactly [0, ∞), matching the target's range
Why this matters: the output activation isn't about "which function tends to work well" — it's about matching the range of g(z) to the range of possible y values. A sigmoid output literally cannot represent a negative stock-price change; a linear output can't be constrained to represent a probability.

8. Choosing the activation for hidden layers

Default recommendation: use ReLU in hidden layers. This is stated directly as "how I pretty much always choose" — not one option among equals.

Two concrete reasons ReLU dominates sigmoid in hidden layers today, even though early neural networks used sigmoid everywhere:

  1. Compute cost: ReLU is just max(0, z); sigmoid needs an exponentiation and a division — slower per-neuron.
  2. Flat regions slow down gradient descent: sigmoid is flat on both ends (z very negative and z very positive). ReLU is flat only on one side (z < 0). More flat regions in the activation ⇒ more flat regions in the cost function J(W,B) ⇒ near-zero gradients ⇒ gradient descent crawls.

Intuition, stated carefully as intuition: more flat regions in activation functions tend to create more flat regions in the cost surface, which can slow gradient descent. Empirically, ReLU trains faster.

Analogy: gradient descent finding the minimum is like rolling a ball downhill. On a sigmoid-heavy landscape there are wide flat plateaus where the ball barely moves even though it isn't at the bottom yet. ReLU's landscape has fewer such plateaus, so the ball keeps rolling.
Other activations you may see in papers: tanh, Leaky ReLU, swish. These show up occasionally and sometimes edge out plain ReLU — Leaky ReLU is mentioned as one worth knowing — but ReLU is described as good enough for the large majority of cases.

9. Lab intuition: how ReLU's "off" switch builds complex shapes

From the optional lab (C2_W2_Relu.ipynb): a small regression network with 3 first-layer units and 1 fixed-sum output unit is used to fit a target function made of three straight-line segments (piecewise linear).

Setup: Unit 0 is pre-fixed to cover the first segment. You adjust w1, b1 for the second segment, then w2, b2 for the third — leaving the others at zero until needed.

Each ReLU unit is "off" (outputs 0) until its transition point, then contributes a new slope. The output layer just sums all three — the "off" switching is what lets a sum of straight lines approximate a bent, piecewise target.

Why this matters: this is the concrete mechanism behind "non-linearity gives expressive power" from Section 5. Each ReLU unit is a switch: below its threshold it contributes nothing, above it contributes a linear piece. Combining many such switches lets the network stitch together arbitrarily complex piecewise-linear (and, with enough units, near-arbitrary curved) functions — something no amount of purely linear composition could do.
Analogy: think of each ReLU unit as a ramp that only starts rising past a certain point on the x-axis, and stays flat at zero before that. Add up several ramps with different starting points and slopes, and you can approximate almost any bent curve — like building a flight of stairs out of ramps that each kick in at a different step.
