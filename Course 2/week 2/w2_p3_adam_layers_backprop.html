1. The problem with a fixed learning rate

Plain gradient descent uses one learning rate α for every parameter, held constant across the whole run:

wj ← wj − α · ∂J(w,b)/∂wj

Left: every step points the same way — α is too small, wasting time. Right: steps bounce across the valley — α is too large.

Why this matters: the "right" learning rate isn't fixed — it depends on the local shape of the cost surface, which changes as training proceeds and differs across parameters. A single global α is a compromise that's rarely ideal everywhere.

2. The Adam algorithm

Adam stands for Adaptive Moment estimation. The name comes from the authors — don't over-read it. The key behavioral idea from lecture: if a parameter keeps moving the same direction step after step, increase its learning rate (go faster); if it keeps oscillating back and forth, decrease its learning rate (calm down).

w1 ← w1 − α1 · ∂J/∂w1    ⋮    w10 ← w10 − α10 · ∂J/∂w10    b ← b − α11 · ∂J/∂b
Not one α — many: if you have parameters w1...w10 and b, Adam tracks 11 separate learning rates, one per parameter, each adapting on its own.

What's actually going on underneath (beyond lecture detail, for grounding)

Adam combines two older ideas:

  • Momentum: instead of reacting only to the current gradient, it keeps a running average of recent gradients. If recent gradients keep pointing the same way, that average builds up "velocity," pushing steps further in that direction — this is the mechanism behind "if moving consistently, speed up."
  • RMSprop: it also keeps a running average of the squared gradients per parameter, and divides the step by (roughly) the square root of that average. A parameter whose gradient has been large/erratic gets its effective step size shrunk — this is the mechanism behind "if oscillating, slow down."
Analogy: imagine walking downhill in fog, feeling your way by the last few steps' slope rather than just the ground right under your foot (that's momentum — smooths out noise, builds speed on a consistent slope). At the same time, if the ground has recently been jerking you sideways a lot, you instinctively take smaller, more careful steps there (that's RMSprop — caution scaled to recent volatility).
Practical takeaway from lecture: Adam still needs an initial global learning rate α (commonly 10-3 as a starting point worth experimenting with), but because it adapts per-parameter, it's more forgiving of an imperfect choice than plain gradient descent — and it's described as the de facto standard most practitioners default to today.

3. Adam in TensorFlow — the MNIST example

What is MNIST? Not introduced explicitly in these lecture transcripts beyond "handwritten digit recognition," but it's worth naming directly: MNIST is a standard benchmark dataset of 70,000 grayscale images of handwritten digits (0–9), each 28×28 pixels, split into 60,000 for training and 10,000 for testing. It's the classic first dataset used to demonstrate digit-classification networks — the same running example this course has used all along (0-vs-1, then all 10 digits).

Switching to Adam only changes the compile step — the model architecture and fit call stay the same as any other multiclass network:

model = Sequential([
    Dense(units=25, activation='sigmoid'),
    Dense(units=15, activation='sigmoid'),
    Dense(units=10, activation='linear')
])

model.compile(
    optimizer=tf.keras.optimizers.Adam(learning_rate=1e-3),
    loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True)
)

model.fit(X, Y, epochs=100)
Why this matters: the only change from everything covered so far is the optimizer= argument in compile() — swapping the plain gradient-descent optimizer for Adam. Everything else (architecture, from_logits=True, the preferred linear-output pattern from Part 2) carries over unchanged.

4. Alternative layer types: the convolutional layer

Every layer used so far is a dense layer: each neuron sees every activation from the previous layer. A convolutional layer instead restricts each neuron to a small window of the input.

Example: EKG signal classification

Input: 100 numbers x1...x100 (heights of an EKG curve at 100 time points). Goal: classify presence/absence of a heart condition.

Windows can overlap (unit 1 covers x1–20, unit 2 covers x11–30) — each neuron only ever sees its own limited slice of the input, never the whole signal.

A second convolutional layer can be stacked on top, with its own units each looking at only a few of the previous layer's activations (e.g. one unit looking at a1[1]–a5[1], another at a3[1]–a7[1]), before a final sigmoid output unit looks at all of those to make the binary prediction.

Why this matters: restricting each neuron to a small window (instead of the entire input) speeds up computation and, notably, can mean the network needs less training data and is less prone to overfitting — because each neuron has far fewer parameters to learn.
Terminology: a network built from one or more convolutional layers is a convolutional neural network (CNN). Architectural choices — window size per neuron, number of neurons per layer — are design decisions, not fixed rules. Not required for this course's homework, but useful intuition: many modern architectures (transformers, LSTMs, attention models) are, at their core, research into new layer types to combine as building blocks, in the same spirit as this.
Analogy: a dense layer neuron is like a person who has to read the entire newspaper before forming an opinion on one sentence. A convolutional layer neuron is more like a proofreader assigned to check just one paragraph — faster, needs less context, and multiple proofreaders can specialize in different sections.

5. The computation graph

The computation graph is how TensorFlow (and deep learning frameworks generally) automatically compute derivatives — by breaking a calculation into small steps connected as a graph of nodes.

Worked example: tiny 1-layer network

Single linear-activation output unit: a = wx + b. Cost J(w,b) = ½(a−y)². Values: w=2, b=8, x=−2, y=2.

The graph nodes are just the intermediate quantities of the calculation, computed one at a time, each depending only on the node(s) before it.

Why this matters: breaking J(w,b) into small labeled steps (c, a, d) is what makes it possible to compute derivatives systematically, one small step at a time, instead of needing to differentiate the whole expression at once.

6. Backprop: computing derivatives right-to-left

Forward prop computes the graph left→right. Backpropagation computes derivatives right→left — starting from J and working backward to find ∂J/∂w and ∂J/∂b.

The logic, one step at a time

At each node, ask: "if this node's input went up by a tiny amount ε, how much would J change?" That ratio is the derivative.

Each derivative is computed once, moving right to left, and reused by the steps before it — this reuse is the entire efficiency trick (Section 7).

Worked numbers, one hop

d → J: if d↑0.001, J↑0.002  ⟹  ∂J/∂d = 2
a → d: if a↑0.001, d↑0.001, and d↑0.001 makes J↑0.002  ⟹  ∂J/∂a = 2
c → a: if c↑0.001, a↑0.001  ⟹  ∂J/∂c = 2   (same for b: ∂J/∂b = 2)
w → c: if w↑0.001, c changes by x·0.001 = −2×0.001  ⟹  ∂J/∂w = −4
This is the chain rule. ∂J/∂c = (∂a/∂c) · (∂J/∂a) = 1 × 2 = 2. You don't need to know calculus notation to follow the logic — each step just asks "how much does a tiny nudge here ripple through to J" and multiplies the local effect by the already-known downstream effect.
Why right-to-left, not left-to-right? To know how w affects J, you first need to know how c affects J — which needs how a affects J — which needs how d affects J. Each answer depends on the next node's answer already being known, so the natural order is to start at J and work backward.

7. Why backprop is efficient

N nodes, P parameters → backprop computes all derivatives in roughly N + P steps, not N × P steps
N (nodes)P (parameters)N + PN × P
10,000100,000110,0001,000,000,000
Why this matters: the key saving is reuse. ∂J/∂a only ever gets computed once, then reused to compute both ∂J/∂w[1] and ∂J/∂b[1] (and anything else further back that depends on a). Compute each intermediate derivative once, on the way back, and every parameter derivative falls out of quantities already known — instead of redoing a full independent calculation per parameter.
Analogy: it's like calculating a delivery route's total cost sensitivity to each stop by walking the route once backward from the destination, noting the cumulative effect at each stop — versus recalculating the entire route from scratch for every single stop you're curious about. One backward walk beats redoing the whole trip per question.
Bigger example from lecture: a 2-layer ReLU network (x=1, y=5, w[1]=2, b[1]=0, w[2]=3, b[2]=1) is walked through the same way — forward to get a[1]=2, a[2]=7, J=2, then backward to get all four parameter derivatives — explicitly contrasting the "inefficient" N×P approach against the "efficient" backprop N+P approach on the same numbers.
