1. Why This Matters: For-Loops vs. Vectorization

Recall the dense() function from the NumPy-from-scratch lecture — it works, but it loops over units one at a time with a Python for loop. That's fine for 3 units. It's painfully slow for a layer with thousands of units, which is completely normal in real deep learning.

Same computation, same result [1,0,1] — left uses a for-loop, right replaces the whole loop with matrix multiplication
Why this matters — this is the whole point of the section: GPUs and modern CPUs are built to do large matrix multiplications extremely fast, in parallel. A Python for loop processes one number at a time, sequentially — it can't take advantage of that parallel hardware at all. Replacing the loop with a single matrix multiplication (np.matmul) lets the exact same math run dramatically faster. This single idea — vectorization — is a major reason deep learning became practical at today's scale. Without it, training large networks would simply take too long to be usable.

Both versions compute the identical thing. The left is what you already built. The right is the same operation, just expressed as one matrix multiplication instead of a manual loop. Understanding why they're equivalent is the goal of this whole section — once that clicks, the vectorized code stops looking like a trick and starts looking obvious.

2. Building Block 1 — The Dot Product

Everything here builds up from one simple operation you already know: the dot product between two vectors.

a = [1, 2],   w = [3, 4]
a · w = (1×3) + (2×4) = 3 + 8 = 11

General rule: multiply corresponding elements together, then add up all the products.

Analogy: A dot product is like a weighted checklist — you're pairing up two lists item-by-item, multiplying each pair, and summing the results into one single number. This is exactly what z = w·x + b has been doing this entire week, just now we're about to formalize the notation around it.

3. Building Block 2 — The Transpose

The same dot product can be written a second way, using matrix notation instead of vector notation — and this second form is the key that unlocks matrix multiplication.

Column vector → row vector

a = [1, 2] written as a column:   1
2  → transpose (aᵀ) → lay it on its side → 1  2

The transpose just takes a matrix (or vector) and lays its columns down as rows. A 2×1 column vector becomes a 1×2 row vector.

a·w  =  aᵀ × w

These are two ways of writing the exact same number. The first is "vector dot product" notation from Course 1. The second — aᵀ × w — is standard matrix multiplication notation: a 1×2 matrix times a 2×1 matrix, which produces a single number.

Why this matters: This equivalence is the entire bridge between "dot products of vectors" (which you already understood from Course 1 logistic regression) and "matrix multiplication" (which sounds intimidating but is really just many dot products, organized neatly into rows and columns).

4. Vector × Matrix Multiplication

Next step up: multiply a row vector by a full matrix (not just another vector).

aᵀ = [1, 2]     W = 3  5
4  6

To compute Z = aᵀ × W, take the dot product of aᵀ with each column of W, one column at a time:

Z₁ = [1,2]·[3,4] = 1×3 + 2×4 = 11
Z₂ = [1,2]·[5,6] = 1×5 + 2×6 = 17
Z = [11, 17]  (a 1×2 matrix)
Why this matters: Notice the pattern — each output number comes from dot-producting the row vector with one column of the matrix. This "take a row, dot it with a column" pattern is the entire mechanism of matrix multiplication. Everything from here just repeats this same operation for more rows and more columns.

5. Matrix × Matrix Multiplication — the General Rule

Now generalize from one row to many rows: multiplying a full matrix Aᵀ by a full matrix W.

Mental model: think in columns

Think of matrix A as a set of column vectors stacked side by side: a₁, a₂, a₃, .... Its transpose Aᵀ lays those same vectors down as rows: a₁ᵀ, a₂ᵀ, a₃ᵀ. Likewise think of W as columns w₁, w₂, w₃, w₄.

Z = Aᵀ × W

The rule for any single element of Z

The number in row i, column j of Z = (row i of Aᵀ) dot (column j of W).
A is 2×3, Aᵀ is 3×2, W is 2×4 → result Z is 3×4. Each Z entry = one row of Aᵀ dotted with one column of W.

Worked examples from this exact slide:

Z positionComputationResult
Row 1, Col 1[1, 2] · [3, 4]11
Row 3, Col 2[0.1, 0.2] · [5, 6]1.7
Row 2, Col 3[-1, -2] · [7, 8]-23
Why this matters: Matrix multiplication is not some new exotic operation — it's literally a grid of ordinary dot products, one per output cell, systematically organized. If you can compute one dot product, you already know how to compute an entire matrix multiplication, one cell at a time.

6. The Shape-Compatibility Rule

You can't multiply just any two matrices — there's exactly one requirement, and it comes directly from the dot-product mechanics above.

The rule: To compute Aᵀ × W, the number of columns of Aᵀ must equal the number of rows of W.

Why: every entry of Z is a dot product between a row of Aᵀ and a column of W. A dot product only makes sense between two vectors of the same length — you can't dot-product a length-2 vector with a length-3 vector. So the "inner" dimensions have to match.

(m × n)  ×  (n × p)  =  (m × p)

In the worked example: Aᵀ is 3×2, W is 2×4 — the inner numbers (2 and 2) match, so multiplication is valid, and the result Z takes the outer dimensions: 3×4.

PropertyRule
Compatibilitycolumns of left matrix = rows of right matrix
Result shape(rows of left) × (columns of right)
Why this matters: This is the #1 thing to check when you get a shape-mismatch error from np.matmul — and you will get this error, probably often, once you start building real networks. Before debugging anything else, check: do the inner dimensions of my two matrices actually match?

7. Doing This in NumPy — the Actual Code

Now the code that implements everything above.

Defining A, its transpose, W, and computing Z with np.matmul
A = np.array([[1, -1, 0.1],
              [2, -2, 0.2]])          # 2x3

# Two ways to get the transpose — both identical:
AT = np.array([[1, 2],
               [-1, -2],
               [0.1, 0.2]])            # written out manually

AT = A.T                                 # or: use NumPy's built-in transpose

W = np.array([[3, 5, 7, 9],
              [4, 6, 8, 0]])           # 2x4

Z = np.matmul(AT, W)                    # matrix multiplication
# equivalently: Z = AT @ W              # '@' is shorthand for matmul

print(Z)
# [[11,   17,  23,   9],
#  [-11, -17, -23,  -9],
#  [1.1,  1.7, 2.3, 0.9]]
CodeMeaning
A.TNumPy's built-in transpose — no need to retype the matrix by hand
np.matmul(X, Y)Matrix multiplication of X and Y
X @ YShorthand operator for the exact same thing as np.matmul(X, Y)
Both np.matmul(...) and @ do identical things. The course sticks with np.matmul for clarity, but you'll see @ used often in other people's code — worth recognizing both.

8. Putting It All Together — the Vectorized Dense Layer

Now apply this directly to the coffee roasting network — replacing the entire for-loop version of dense() with matrix multiplication.

Setup: everything as 2D arrays/matrices

AT = np.array([[200, 17]])              # 1x2 — input features (note: DOUBLE brackets)

W = np.array([[1, -3, 5],
              [-2, 4, -6]])              # 2x3 — 2 features, 3 units (columns = each unit's weights)

b = np.array([[-1, 1, 2]])               # 1x3 — one bias per unit (also 2D now)

The vectorized dense() function

def dense(AT, W, b):
    Z = np.matmul(AT, W) + b
    A_out = g(Z)          # g = sigmoid, applied element-wise
    return A_out

Compare this to the loop-based version from the previous lecture — the entire for j in range(units): ... block collapses into one line: Z = np.matmul(AT, W) + b.

Verifying by hand — same numbers, new method

Z = Aᵀ·W + b
Z₁ = (200×1 + 17×(-2)) + (-1) = 200 - 34 - 1 = 165
Z₂ = (200×(-3) + 17×4) + 1 = -600 + 68 + 1 = -531
Z₃ = (200×5 + 17×(-6)) + 2 = 1000 - 102 + 2 = 900

Then A = g(Z) = sigmoid([165, -531, 900]). Since sigmoid saturates for large inputs: sigmoid(165) ≈ 1, sigmoid(-531) ≈ 0, sigmoid(900) ≈ 1 → final result A = [1, 0, 1].

Why this matters: This is the exact same [1, 0, 1] result as the for-loop version from Section 1 — proof that vectorization changes how the computation is expressed and executed, not what it computes. Same math, same answer, radically faster execution.

9. One Wrinkle: Why TensorFlow's Code Looks Slightly Different

If you compare this slide's variable name AT (meaning "A transpose," i.e. a row of features) to earlier TensorFlow code, you'll notice TensorFlow labels the same thing a_in instead of AT. That's not a mathematical difference — it's a naming/orientation convention.

TensorFlow's convention: individual training examples are laid out as rows of the input matrix X directly (not Xᵀ). This matches exactly what you saw earlier: X = np.array([[200.0, 17.0], [120.0, 5.0], ...]) — one row per example. So what the lecture slide calls "Aᵀ" is, in TensorFlow's own convention, simply called the input matrix, no transpose framing needed — TensorFlow already stores examples row-wise by default.
Why this matters: This resolves any confusion between "the math slide's transpose notation" and "the TensorFlow code you already used." They're not contradicting each other — they're two equally valid ways of laying out the same numbers, and TensorFlow's Dense/Sequential API was designed around the row-per-example convention specifically so you never have to think about transposing your input data yourself.

ConceptKey fact
Dot productMultiply corresponding elements, sum the results → one number
Transpose (ᵀ or .T)Lays columns down as rows — turns a column vector into a row vector

Why it's fasterMatrix multiplication runs in parallel on GPUs/CPUs; for-loops run sequentially
Big-picture analogy: The for-loop version of dense() is like one cashier serving customers one at a time. The vectorized version is like opening every checkout lane simultaneously — same total work gets done, same final receipts, just handled in parallel instead of sequentially. Modern hardware (GPUs especially) is built to be that "whole row of cashiers," and matrix multiplication is the instruction that tells it to actually use them all at once.
