1. Why Implement This From Scratch At All

Almost nobody implements forward propagation by hand in production — everyone uses TensorFlow or PyTorch. So why do this?

Why this matters: The moment something goes wrong in a real project — training doesn't converge, results look wrong, a shape mismatch error appears — your ability to debug it depends entirely on understanding what's happening inside the library call. If Dense and Sequential are total black boxes to you, you can only guess at fixes. If you've built the same thing yourself in NumPy, you know exactly what a "layer" mathematically does, so you can reason about the bug instead of guessing.

This lecture builds the exact same "coffee roasting" network from the TensorFlow lab — same architecture, same weights — but computes every number using nothing but NumPy dot products and a manual sigmoid.

2. Version 1 — The Fully Hardcoded Version

The most literal, unrolled way to implement forward prop: write one line of code per neuron, by hand.

Every neuron gets its own explicit w, b, z, a — nothing is looped or generalized yet

Notation note

In this hand-written code, w1_1 means w superscript [1] subscript 1 — i.e. the weight vector of the 1st neuron in layer 1. The underscore is just how you write a subscript in plain code (no superscript/subscript formatting available).

Layer 1 (3 neurons) — one block of code per neuron

x = np.array([200, 17])          # 1D array this time — no double brackets

# --- Neuron 1 of layer 1 ---
w1_1 = np.array([1, 2])
b1_1 = np.array([-1])
z1_1 = np.dot(w1_1, x) + b1_1
a1_1 = sigmoid(z1_1)

# --- Neuron 2 of layer 1 ---
w1_2 = np.array([-3, 4])
b1_2 = np.array([1])
z1_2 = np.dot(w1_2, x) + b1_2
a1_2 = sigmoid(z1_2)

# --- Neuron 3 of layer 1 ---
w1_3 = np.array([5, -6])
b1_3 = np.array([2])
z1_3 = np.dot(w1_3, x) + b1_3
a1_3 = sigmoid(z1_3)

# Group outputs into the layer's activation vector
a1 = np.array([a1_1, a1_2, a1_3])
Notice the bracket change from earlier: x = np.array([200, 17]) here uses single brackets — a plain 1D array — not the double-bracket 2D matrix TensorFlow wanted. That's deliberate: this manual NumPy version processes one example at a time as a flat vector, rather than a batch matrix. Different context, different convention — both are "correct," just for different tools.

Layer 2 (1 neuron) — takes a1 as its input

w2_1 = np.array([-7, 8, 9])
b2_1 = np.array([3])
z2_1 = np.dot(w2_1, a1) + b2_1
a2_1 = sigmoid(z2_1)

That's it — a2_1 is the network's final output, exactly the same computation as the TensorFlow version, just written out neuron-by-neuron instead of calling Dense().

Why start this way: This version is intentionally tedious. It's meant to make the underlying math (a dot product + bias + sigmoid, repeated) completely undeniable and concrete before compressing it into a reusable function next.

3. Version 2 — The General dense() Function

Hardcoding one block per neuron doesn't scale — a layer with 25 units would mean 25 copy-pasted blocks. The fix: write one function that works for a layer of any size, using a for loop over units and a weight matrix instead of separate vectors.

Stack all neurons' weight vectors as columns of one matrix W; loop over columns to compute each unit's output

Step 1: stack weights into a matrix, biases into a vector

Instead of separate w1_1, w1_2, w1_3, stack them as the columns of one matrix:

W = np.array([
    [1, -3, 5],
    [2,  4, -6]
])          # shape (2, 3) — 2 input features, 3 units
            # column 0 = w1_1, column 1 = w1_2, column 2 = w1_3

b = np.array([-1, 1, 2])   # one bias per unit, shape (3,)
Convention reminder: capital W = matrix, lowercase w, a, b = vectors/scalars — standard linear algebra notation, and TensorFlow/NumPy code follows it too.

Step 2: the general dense() function

def dense(a_in, W, b):
    units = W.shape[1]          # number of columns of W = number of units in this layer
    a_out = np.zeros(units)     # placeholder, e.g. [0, 0, 0] for 3 units
    for j in range(units):      # loop over each unit: j = 0, 1, 2, ...
        w = W[:, j]              # pull out the j-th COLUMN of W → weights for unit j
        z = np.dot(w, a_in) + b[j]
        a_out[j] = g(z)          # g = sigmoid (defined once, outside this function)
    return a_out
LineWhat it's doing
W.shape[1]Number of columns of W = number of neurons/units in this layer
np.zeros(units)Empty output array to fill in, sized correctly upfront
W[:, j]NumPy slicing syntax: "all rows, column j" → pulls out one neuron's full weight vector
np.dot(w, a_in) + b[j]The z computation for unit j — identical math to before, just indexed by j now
a_out[j] = g(z)Store this unit's activation in the right slot
Why this matters: This one function replaces the entire hardcoded block from Section 2 — for a layer of 3 units or 300 units, the code doesn't change, only W's shape does. This is the real leap from "I understand the math for one neuron" to "I can build a layer of arbitrary size."

Note the activation function g is defined once, outside dense(), e.g. g = sigmoid — kept simple since this course only uses sigmoid here. (You'll later see it passed in as a parameter, e.g. dense(a_in, W, b, g), once different activation functions are introduced next week.)

4. Chaining Layers with sequential()

With dense() defined, building a full multi-layer network is just calling it repeatedly, feeding each layer's output into the next:

def sequential(x):
    a1 = dense(x,  W1, b1)
    a2 = dense(a1, W2, b2)
    a3 = dense(a2, W3, b3)
    a4 = dense(a3, W4, b4)
    f_x = a4
    return f_x

This mirrors exactly what TensorFlow's Sequential([...]) + .predict() does internally — a chain of dense-layer calls, each one's output becoming the next one's input.

Full worked example — layer 1 of the coffee network, using dense()

W = np.array([
    [1, -3, 5],
    [2,  4, -6]
])                              # 2 x 3
b = np.array([-1, 1, 2])

a_in = np.array([-2, 4])        # a[0] = x, the input features

a1 = dense(a_in, W, b)          # runs the for-loop above, returns 3 activation values
Why this matters: This is the complete recipe: dense() is the reusable "layer" building block, and sequential() is just a fixed sequence of calls to it. Once you have these two functions, you have re-derived, from first principles, everything TensorFlow's Dense + Sequential classes do under the hood for forward propagation.

This lab rebuilds the exact same coffee roasting network from Lab 02 — but with zero TensorFlow layers, only NumPy.

X, Y = load_coffee_data()

Interesting detail: TensorFlow's Normalization layer is still used here — it's a data preprocessing utility, not a trained model layer, so borrowing it doesn't defeat the point of building the model itself from scratch.

Step 2 — The activation function 
g = sigmoid    # imported from lab_utils_common.py
Step 3 — my_dense(): the reusable layer function 
def my_dense(a_in, W, b):
    """
    a_in (ndarray (n,))   : input, n features, 1 example
    W    (ndarray (n,j))  : weight matrix, n features per unit, j units
    b    (ndarray (j,))   : bias vector, j units
    Returns a_out (ndarray (j,)) : activations of this layer's j units
    """
    units = W.shape[1]
    a_out = np.zeros(units)
    for j in range(units):
        w = W[:, j]
        z = np.dot(w, a_in) + b[j]
        a_out[j] = g(z)
    return a_out

Identical to the lecture's dense() — the docstring is the useful addition here, spelling out expected shapes precisely: W is (n_features, n_units), matching the weight-shape rule from the TensorFlow lab.

Step 4 — my_sequential(): chaining the 2 layers 
def my_sequential(x, W1, b1, W2, b2):
    a1 = my_dense(x,  W1, b1)
    a2 = my_dense(a1, W2, b2)
    return a2
Step 5 — Reuse the already-trained weights 
W1_tmp = np.array([[-8.93, 0.29, 12.9], [-0.1, -7.32, 10.81]])
b1_tmp = np.array([-9.82, -9.28, 0.96])
W2_tmp = np.array([[-31.18], [-27.59], [-32.56]])
b2_tmp = np.array([15.41])
These are the trained weights copied straight from the TensorFlow lab (Lab 02) — nearly identical to the ones you inspected there, just from a slightly different training run. The point is: this NumPy implementation doesn't train anything itself (no gradient descent here) — it only re-implements inference (forward propagation) using weights someone else already learned.
Step 6 — my_predict(): TensorFlow's .predict(), built by hand 
def my_predict(X, W1, b1, W2, b2):
    m = X.shape[0]              # number of examples (rows)
    p = np.zeros((m, 1))
    for i in range(m):
        p[i, 0] = my_sequential(X[i], W1, b1, W2, b2)
    return p

This is the missing piece connecting single-example my_sequential() to batch prediction: loop over every row of X, run one example through the network, store the result. This is literally what model.predict(X) does for you automatically in TensorFlow — Section 6 makes this comparison explicit.

Step 7 — Predict and threshold, same as before 
X_tst = np.array([
    [200, 13.9],   # positive example
    [200, 17]])    # negative example
X_tstn = norm_l(X_tst)   # normalize with the SAME norm_l from training

predictions = my_predict(X_tstn, W1_tmp, b1_tmp, W2_tmp, b2_tmp)
yhat = (predictions >= 0.5).astype(int)

Identical logic to Lab 02 — normalize new data with the training-fitted normalizer, predict, threshold at 0.5.

Step 8 — Verify against TensorFlow's result 
netf = lambda x: my_predict(norm_l(x), W1_tmp, b1_tmp, W2_tmp, b2_tmp)

Why this matters: The lab explicitly states this produces a graph identical to the TensorFlow version from Lab 02.
