1. Inference in Code — the Coffee Roasting Example

New running example: predicting whether a coffee roast is good (y=1) or bad (y=0) from two features — temperature and duration. Good coffee only happens in a narrow "sweet spot" triangle: not too cold/short (undercooked), not too hot/long (burnt).

The two-layer network, coded directly

x = np.array([[200.0, 17.0]])          # temperature=200°C, duration=17 min

layer_1 = Dense(units=3, activation='sigmoid')
a1 = layer_1(x)                          # a1 → e.g. [0.2, 0.7, 0.3]

layer_2 = Dense(units=1, activation='sigmoid')
a2 = layer_2(a1)                         # a2 → e.g. [0.8]

if a2 >= 0.5:
    yhat = 1
else:
    yhat = 0
Manual, layer-by-layer forward propagation: x → layer_1 → a1 → layer_2 → a2 → threshold

Dense is the name TensorFlow/Keras uses for the ordinary fully-connected layer type you already know — every neuron connects to every input. It's called "Dense" because the connections are dense (not sparse/selective).

Same pattern, digit classification (3 layers)

x = np.array([[0.0, ..., 245, ..., 240, ..., 0]])   # 64 pixel intensities

layer_1 = Dense(units=25, activation='sigmoid')
a1 = layer_1(x)

layer_2 = Dense(units=15, activation='sigmoid')
a2 = layer_2(a1)

layer_3 = Dense(units=1, activation='sigmoid')
a3 = layer_3(a2)

if a3 >= 0.5:
    yhat = 1
else:
    yhat = 0
64 → 25 → 15 → 1: identical pattern to the coffee example, just deeper and wider
Why this matters: Notice the two examples are structurally identical — create a Dense layer, apply it to get an activation, feed that activation into the next Dense layer. This chain of a = layer(previous_a) calls is forward propagation in code. Once you see the pattern, you can build a network of any depth.

2. How TensorFlow Represents Data

This is the part that quietly breaks people's code later, so it's worth being precise now.

NumPy vs. TensorFlow: a historical mismatch

NumPy predates TensorFlow by many years and became the standard for linear algebra in Python. TensorFlow (built later, partly by the Google Brain team) made different conventions for efficiency at scale. The result: two libraries you'll constantly move data between, with slightly different defaults.

Matrices vs. 1D vectors — the double-bracket rule

Double brackets → 2D matrix. Single brackets → 1D array ("just a list of numbers")
CodeShapeWhat it is
np.array([[200, 17]])1 × 22D matrix, 1 row / 2 columns — a "row vector"
np.array([[200],[17]])2 × 12D matrix, 2 rows / 1 column — a "column vector"
np.array([200, 17])(2,)1D array — no rows/columns, just a flat list
Rule of thumb: Course 1 (linear/logistic regression from scratch) used plain 1D arrays for input features — single brackets. TensorFlow layers expect 2D matrices — double brackets — because TensorFlow was built to process large batches of examples efficiently, and a matrix naturally represents "many rows, each one example." A single 1D vector doesn't carry that "batch" structure.

This is exactly why in the lab you always see input reshaped or written with double brackets, e.g. X_train[0].reshape(1,1) or np.array([[200.0, 17.0]]) — even a single example must look like a matrix with 1 row.

Matrix dimension convention

dimensions = (number of rows) × (number of columns)

E.g. a matrix with 2 rows and 3 columns is written as 2 × 3.

What comes out: tensors

When you call a1 = layer_1(x), the result isn't a NumPy array — it's a tensor, TensorFlow's own data structure for efficiently storing and computing on matrices.

a1
# <tf.Tensor: shape=(1, 3), dtype=float32, numpy=array([[0.2, 0.7, 0.3]], dtype=float32)>

a1.numpy()   # converts back to a plain NumPy array, e.g. array([[0.2, 0.7, 0.3]])
TermMeaning
TensorTensorFlow's internal representation of a matrix (a bit more general mathematically, but treat it as "a matrix" for this course)
float32A decimal number stored using 32 bits — TensorFlow's default numeric precision
.numpy()Converts a TF tensor back into a plain NumPy array
Why this matters: If you ever get a shape mismatch error, or your array "looks right" but TensorFlow complains, the very first thing to check is: is this a 1D array or a proper 2D matrix? And is it a NumPy array or a TF tensor? These two axes of confusion cause the majority of early TensorFlow bugs.

3. Building the Full Network with Sequential

Manually chaining a1 = layer_1(x), a2 = layer_2(a1) works, but TensorFlow gives you a cleaner way to package the whole network as one object: Sequential.

The coffee roasting network, built with Sequential

Sequential strings the layers together into one callable model
model = Sequential([
    Dense(units=3, activation="sigmoid"),
    Dense(units=1, activation="sigmoid")
])

X = np.array([[200.0, 17.0],
              [120.0, 5.0],
              [425.0, 20.0],
              [212.0, 18.0]])          # 4 x 2 — 4 training examples, 2 features
Y = np.array([1, 0, 0, 1])             # targets, 1D array of length 4

model.compile(...)      # defines the loss function + optimizer (Week 2 detail)
model.fit(X, Y)          # trains the weights (backprop — Week 2 detail)

model.predict(X_new)     # runs forward propagation for you, all layers at once
CallWhat it does
Sequential([...])Strings the given layers together, in order, into a single network object
model.compile(...)Configures how training will happen (loss function, optimizer) — details next week
model.fit(X, Y)Runs the training algorithm (gradient descent / backprop) to learn W and b
model.predict(X_new)Runs forward propagation through all layers automatically — replaces manually calling each layer yourself
Convention: in real TensorFlow code, you rarely see layers assigned to separate variables like layer_1, layer_2. They're almost always written directly inline inside the Sequential([...]) call, exactly as shown above.
Why this matters — and why "just 5 lines of code" isn't the whole story: Sequential/compile/fit/predict hide the exact same forward-propagation math you already coded manually in Section 1 — nothing new is happening mathematically. The real skill isn't memorizing these 4 calls; it's knowing what they're doing underneath: chaining Dense layers, each computing g(w·a + b), and gradient descent iteratively adjusting w and b to minimize a loss. Andrew Ng makes this point explicitly — that's exactly why the course has you implement forward propagation from scratch in Python next (no TensorFlow at all), so the "5 lines of magic" stop being magic.

4. Lab 02 Deep Dive — Coffee Roasting, Line by Line

This is the actual notebook implementation. Walking through every meaningful step, not just the headline code.

Step 1 — Load and inspect data 
X, Y = load_coffee_data()
print(X.shape, Y.shape)   # X: (m, 2) — m examples, 2 features (temp, duration)
                            # Y: (m, 1) — labels, 1 = good roast, 0 = bad roast

The data forms a small triangular "good roast" region when plotted (temp vs. duration) — this is why a single straight-line decision boundary (plain logistic regression) can't solve it well, but a neural network with a hidden layer can.

Step 2 — Normalize the features 
norm_l = tf.keras.layers.Normalization(axis=-1)
norm_l.adapt(X)     # computes mean & variance of X, stores them internally
Xn = norm_l(X)       # applies (x - mean) / std to every feature
Why normalize: Temperature ranges roughly 175–260, duration ranges roughly 12–20 — very different scales. Gradient descent (used in .fit(), covered next week) converges much faster and more reliably when all features are on a similar scale. This is the same normalization idea from Course 1 — just implemented here as its own Keras layer instead of manual code.
Important: norm_l is not part of the model — it's a separate preprocessing step. Any new data you want to predict on later must be normalized with this exact same norm_l (same learned mean/variance) before being passed to the model.
Step 3 — Artificially expand the training set 
Xt = np.tile(Xn, (1000,1))   # copies the data 1000 times → shape (m*1000, 2)
Yt = np.tile(Y,  (1000,1))

This is a lab-specific trick (not a general technique) purely to reduce the number of training epochs needed for a tiny dataset to converge — not something you'd do with real, larger datasets.

Step 4 — Define the model 
tf.random.set_seed(1234)   # for reproducible results
model = Sequential([
    tf.keras.Input(shape=(2,)),
    Dense(3, activation='sigmoid', name='layer1'),
    Dense(1, activation='sigmoid', name='layer2')
])

tf.keras.Input(shape=(2,)) declares upfront "each example has 2 features." This lets TensorFlow immediately size and allocate the weight matrices, which is convenient when you want to inspect the model before training. Without it, TensorFlow infers the shape automatically the first time you call .fit().

Step 5 — Inspect the parameter shapes (this is the part that builds real understanding) 
model.summary()

L1_num_params = 2 * 3 + 3   # W1: (2 inputs × 3 units) weights + 3 biases = 9
L2_num_params = 3 * 1 + 1   # W2: (3 inputs × 1 unit) weights + 1 bias = 4
LayerWeight matrix shapeBias shapeRule
layer1 (3 units)W1: (2, 3)b1: (3,)(n_inputs, n_units)
layer2 (1 unit)W2: (3, 1)b2: (1,)(n_inputs, n_units)
Why this matters: This is the single most useful mental habit for debugging any neural network — a Dense layer's weight matrix always has shape (number of inputs it receives, number of units it has), and its bias always has shape (number of units,). If you can predict these shapes before printing them, you truly understand what the layer is doing — it's not "some black box producing outputs," it's a very specific, sized linear-algebra operation. 
W1, b1 = model.get_layer("layer1").get_weights()
W2, b2 = model.get_layer("layer2").get_weights()
Step 6 — Compile and train 
model.compile(
    loss=tf.keras.losses.BinaryCrossentropy(),
    optimizer=tf.keras.optimizers.Adam(learning_rate=0.01),
)

model.fit(Xt, Yt, epochs=10)

Full detail comes next week (this is your first hint at loss functions and gradient descent variants like Adam), but for now: fit repeatedly runs forward propagation, measures how wrong the predictions are (via the loss), and nudges every W and b slightly to reduce that error — epochs=10 means this whole cycle repeats 10 times over the (tiled) dataset.

Step 7 — Set known weights (for reproducibility in the lab) 
W1 = np.array([[-8.94, 0.29, 12.89],
               [-0.17, -7.34, 10.79]])
b1 = np.array([-9.87, -9.28, 1.01])
W2 = np.array([[-31.38],[-27.86],[-32.79]])
b2 = np.array([15.54])

model.get_layer("layer1").set_weights([W1, b1])
model.get_layer("layer2").set_weights([W2, b2])

Since .fit() can converge to slightly different weights each run, the lab loads a known-good set of pretrained weights so the following visualizations behave predictably — swap back to your own trained weights any time.

Step 8 — Predict on new data 
X_test = np.array([
    [200, 13.9],   # expected: good roast
    [200, 17]])    # expected: bad roast

X_testn = norm_l(X_test)             # must normalize with the SAME norm_l
predictions = model.predict(X_testn)

yhat = (predictions >= 0.5).astype(int)   # threshold to get 0/1 decisions
Common bug to avoid: forgetting to normalize new/test data with the same norm_l used on the training data. The model was trained on normalized inputs — feeding it raw, unnormalized numbers will silently produce garbage predictions.
Step 9 — Visualize what each neuron learned (this is the "why it works" payoff) 
plt_layer(X, Y.reshape(-1,), W1, b1, norm_l)   # visualizes each of the 3 layer-1 neurons
plt_output_unit(W2, b2)                          # visualizes the final output neuron
netf = lambda x: model.predict(norm_l(x))
plt_network(X, Y, netf)                          # visualizes the whole network's decision

The lab's visualization reveals something important: each of the 3 hidden neurons specializes on its own, without being told to.

  • Unit 0: fires strongly when temperature is too low (detects "undercooked" region)
  • Unit 1: fires strongly when duration is too short
  • Unit 2: fires strongly for bad combinations of time/temperature
Why this matters: This is the demand-prediction "affordability / awareness / quality" story made concrete and visual with real numbers. Nobody programmed these three neurons to divide up the "bad roast" regions this way — gradient descent discovered this division on its own. It's the clearest possible demonstration of automatic feature learning from Part 1, now backed by an actual trained model you can inspect.

5. The Mental Model: What Actually Happens Underneath

Putting it all together — what's really going on every time you call model.predict(x):

  1. Your input x is a 2D matrix (rows = examples, columns = features).
  2. Layer 1 computes a1 = sigmoid(x @ W1 + b1) — a real matrix multiplication, not a loop over neurons written by hand (though mathematically it's equivalent to computing each neuron's g(w·x + b) separately, just vectorized).
  3. Layer 2 takes a1 as its input and computes a2 = sigmoid(a1 @ W2 + b2).
  4. The result is a tensor; convert with .numpy() if you need a plain array.
  5. Threshold at 0.5 (or whatever cutoff makes sense) to get a hard decision.
Analogy: Sequential + .fit() + .predict() is like using a car's automatic transmission — it's genuinely doing the same physics as a manual transmission (same engine, same gears), just automating the gear-shifting for you. Knowing how to drive an automatic doesn't require understanding the clutch, but a good engineer working on cars still needs to know what's happening under the hood — which is exactly why the course has you implement forward propagation manually in NumPy next, before returning to the TensorFlow shortcuts.
